## 1. 목적과 적용 범위

Intel은 선택한 사이트에서 나타나는 사용의 형태를 이해하는 화면이다.
설정 변경이나 사이트별 교정을 완료해야만 성공하는 작업 흐름으로 만들지 않는다.
화면은 압축하되, 그 이유로 분석 모델의 입력·차원·복합 판단을 축소하지 않는다.

앞선 대화의 사용량·체류·재방문 세 질문은 첫 화면에 검토할 후보이며,
현재 분석 엔진의 범위 또는 최종 분류 체계를 의미하지 않는다.
기존 모델의 다층 결합, 개인 기준, 시간적 상태, 정책 맥락, 근거 계보,
출력 소비처를 먼저 감사한 뒤 유지·보완·분리할 부분을 결정한다.

최초 요청의 1단계 감사는 완료했다. 이어진 사용자 요청에 따라 **확정된
문제와 역류 경계를 먼저 수정**하고, 각 모델층의 보완·확장 계획을 작성했다.
아래 단계 2–4의 경계 수정 일부를 앞당겼다. 이어 기초 모델 교정을 반영했으며
구체적 결과는 15절에 기록한다. 문맥층 교정은 16절에 이어서 기록한다.
순서·결합 모델 교정은 17절, 출력 계약과 기존 패널 연결은 18절에 기록한다.
전체 Intel 리디자인과 실제 제품 이해도 검증은 아직 완료한 것으로 간주하지 않는다.

### 현재 상태 → 목표 상태 / canonical successor

현재는 다층 Site Pull, 일반 insight synthesis, UI의 대표 문장·공개 판정이
공존한다. 활동일/달력일과 관측 가용성의 의미에도 정리할 경계가 있다.
목표는 기존 분석 능력을 유지하면서 같은 사실·근거·주장 계약을 Intel이
소비하도록 만드는 것이다. 독립적인 Intel 분석 엔진을 추가하지 않는다.

전환 후 canonical successor는 위의 Active 문서들이다. 제품 의미·화면 계약은
사이트 탭 PRD, 패턴/판단 소유권은 Site Pull 경계, 비교 기간·개인 참조는 개인
기준 경계와 통계 엔진 기준선, 새 사실·저장 변경은 통계·저장 경계에 반영한다.
각 구현 시 해당 문서를 갱신하며, 전체 전환 완료 후 이 계획은 archive한다.

유지할 원칙:

1. 수집 사실 → 집계 → 특징 → 근거 → 판단 → 표현의 책임을 구분한다.
2. 모델이 복잡해도 사용자에게 보이는 정보량은 별도로 제한한다.
3. UI가 원시 통계, 개인 기준, 임계값, 패턴 우선순위를 재계산하지 않는다.
4. 새 Intel 전용 분석 엔진·저장소·우회 조회·대체 사실 경로를 만들지 않는다.
5. 관측된 0, 기록 없음, 수집 불허, 실측, 추정, 잘린 기록을 구분한다.
6. 정책 효과와 관측 사실을 구분한다. 분석 UI 개선이 보호 실행 강도나
   CLSE 모델 정책을 암묵적으로 바꾸지 않도록 소비처 영향도를 검사한다.
7. 신호의 강도, 근거의 품질, 사용자에게 말할 수 있는 확실성을 구분한다.
8. 동일 행동에서 나온 여러 별칭을 독립 근거로 세지 않는다.
9. 설정·분류·한도 변경으로 행동 자체가 더 안전해진 것처럼 보이지 않게 한다.
10. 모든 수집·가공은 기존 기기 내 저장·권한 계약을 유지한다.

단계들은 순차 진행한다. 독립적인 감사와 사례 검토를 나누더라도 최종
측정 정의·판단 계약은 하나로 통합한다. 단계 종료마다 이 표와 결정 대장을
갱신해 세션이 길어져도 작업 기준을 잃지 않도록 한다.

## 4. 1단계: 전체 모델 감사

### 조사 범위

- 현재 Site Pull 전체: 특징 벡터, 비선형 정규화, 부분 점수, 개인 기준,
  근거 profile, 원자 후보, 요구조건, calibration, 복합 결합, 억제, 출력.
- 그 외 실제 분석·보호 모델: 통계 insights synthesis, CLSE,
  consumption memory 등. Intel과 연결되는지, 별개 실행 정책인지 확인한다.
- 모델이라는 이름과 실제 구현을 구분: 학습되는 파라미터, 고정 가중치,
  임계값, 비선형 변환, 기억/적응 상태, feedback 경로를 각각 추적한다.
- 수집 이벤트부터 durable bucket과 선택 사이트 조회까지의 관측 provenance.
- 전체/보호/기록만/제외, 정밀 관측 허용 여부에 따른 데이터 차이.
- 활동일/달력일/현재 진행 중인 날/장기 개인 기준의 시간 의미.
- 요약치가 보존하거나 잃는 정보: 실제 세션과 누적 구간, 분포, 복귀 gap,
  시간대 반복성, tab/feed lineage, 부분 기록.
- 화면 조회·cache·revision·polling과 대표 판단의 갱신 경계.
- 현재 테스트와 guard가 보장하는 것, 실제 의미 타당성까지 보장하지 않는 것.

### 산출물

완료된 [1단계 감사 보고서](../../reports/site-intel-analysis-stage1-audit-2026-09-14.md)에
현재 코드 경로/함수, 사용자에게 미치는 의미, 우선순위, 확인 방식과 다음
단계의 담당 경계를 기록했다. [순수 재현 결과](../../reports/site-intel-analysis-stage1-probe-2026-09-14.json)도
함께 보존한다.

확정된 결함, 설계상 tradeoff, 데이터 능력의 한계, 아직 검증하지 않은
가설을 분리한다. 구조 검사 PASS를 행동 모델의 정확도 증명으로 쓰지 않는다.

### 검증 범위

읽기와 소스 경로 추적을 기본으로 한다. 구체적인 불일치의 확인에 필요한
경우에만 기존 순수 함수/집중된 테스트로 재현한다. 문서 변경은 경로·메타·
공백 검사를 수행한다. 1단계는 런타임 변경이 없으므로 브라우저 실행,
개발 서버, dist 재생성은 필요하지 않다.

### 1단계에서 확정한 후속 우선순위

- 41개 패턴·14개 근거 profile·15개 개인 기준 지표의 다층 모델을 유지한다.
  학습 신경망으로의 교체는 선행 조건이 아니다.
- 관측 없음/관측된 0의 엔진 상태 합침을 수정하고, 비교 기간과 가용성부터 정한다.
- 행동 형태, 목표 불일치, 근거 품질을 분리한다. 같은 행동의 목표 변경만으로
  행동 자체가 개선되었다는 해석을 제공하지 않는다.
- 일반 insight, Site Pull presenter, UI headline의 역할·소비처를 정리한 뒤
  대표 주장의 권한을 기존 분석 경계로 모은다.
- 완료 30일의 반복 시간 분석은 이미 있다. 기존 정본을 재사용한다.
- 개인 기준 guard에서 발견한 기존 marker 불일치 5개는 실제 추출된 helper의
  소유권 검사를 유지하며 3단계에 정합화한다. 감사 완료가 전체 검사 PASS는 아니다.

## 5. 2단계: 목표 해석 계약과 표현 시안

### 해석 계약

실행 순서는 **기간·관측 상태 → 행동/정책/품질의 의미 → 대표 주장 소유권 →
사례 fixture → 표현 시안**이다. 감사 보고서의 A02/T01/A04/A01/A03/A07을
선행 계약으로 삼고, 임계값 조정이나 UI 카드 재배치부터 시작하지 않는다.

각 통찰은 아래를 정의한다.

- 사용자에게 답하는 질문과 주장하지 않을 의미.
- 필요한 데이터 family, 집계 기간, 분모, 값/단위, 관측 범위.
- 실측·proxy·baseline·정책 맥락의 역할과 허용 노출 수준.
- 반대 근거, 혼합 패턴, 약한 근거, no-claim 상태.
- 비교 창의 겹침, 변화 판단의 정본, 현재 활동일을 별도로 다루는 방식.
- 표시 후보의 안정적 식별자와 provenance. 문구 번역은 기존 i18n 소유.

7개 완료 활동일은 기본 설명 창의 후보이며, 1단계에서 기존 feature와
개인 기준의 시간 계약을 확인한 뒤 확정한다. UI에서 30일 baseline을
7일 집계로 대체하거나 서로 다른 기간의 값을 직접 비교하지 않는다.

### 사례 시안

실제 데이터처럼 위장하지 않는 명시적인 fixture로 확인한다.

- 같은 60분: 두 번의 긴 사용 / 여러 번의 짧은 사용.
- 많은 짧은 확인 + 소수의 긴 방문이 시간을 차지하는 혼합 형태.
- 빠른 복귀가 적은 긴 사용 / 빠른 복귀가 반복되는 짧은 사용.
- background residency와 실제 foreground 사용의 차이.
- 단일 사건 급증 / 여러 완료일에 걸친 지속 변화.
- 높은 개인 baseline / 낮은 baseline에서의 일시적 증가.
- 짧은 의도적 조회를 반복하는 반례, 야간이라는 사실만 있는 반례.
- 관측된 0 / 부분 관측 / 관측 없음 / recording disabled.
- 정밀 기록 없는 사이트와 정밀 신호가 있는 사이트.
- 목표 변경·보호 전환 전후의 동일 행동.

핵심 문장 하나, 주 시각화 하나, 근거 최대 두 개를 우선 검토한다.
그래프 종류는 데이터 계약과 사례 이해도를 보고 정하며, 현재 요일 차트를
다른 장식 차트로 교체하는 것 자체를 완료로 보지 않는다.

## 6. 3단계: 집계와 모델 보완

1단계의 근거 대장에 따라 우선순위를 확정한다. 세 질문을 구현하기 위해
기존의 복합 구조를 제거하지 않는다. 각 변경은 하나의 검증 가능한 작업으로
나누고 collector/store/query/feature/evidence 중 실제 소유 경계에서 처리한다.

- 방문·세션·탭 전환·구간 분할의 정의와 중복 방지.
- 같은 시간 창에서 의미가 맞는 측정치/분포와 정확한 관측 분모.
- 복귀 gap, 반복 맥락, 개인 기준 비교가 보존된 사실로 가능한지 확인.
- 비선형 가중 결합의 포화, 경계 민감도, 동일 계보 중복, sparse 상태.
- 설명 가능한 neutral/mixed 결과와 단정 금지 사례.

새 저장 항목은 기존 자료로 만들 수 없을 때만 도입하며, typed store,
schema/version/retention/collection admission/중단 동작을 함께 설계한다.
과거 집계로 재구성할 수 없는 새 항목은 unavailable로 남기고 backfill을
가장하거나 legacy read 경로를 추가하지 않는다.

검증은 수집·집계의 보존성, 순수 모델의 경계/반례, 공개 DTO의 의미를
각각 확인한다. 모델이 만든 분류를 그대로 테스트 정답으로 복사하지 않는다.

## 7. 4단계: 대표 통찰과 DTO

기존 facts/evidence/presenter/read-model seam을 확장한다. 필요한 concern이
기존 seam에 맞지 않을 때만 named seam과 소유 문서를 함께 추가한다.

- 대표 주장은 가장 높은 경고 점수가 아니라 설명력·근거 품질·중복을 고려.
- 보완/반대 근거와 혼합 형태를 표현할 수 있어야 함.
- 의미 ID, 근거 ID, 값/단위, 기간, coverage, 데이터/모델 버전을 연결.
- 모든 핵심 표시를 같은 분석 결과로 조립. UI에 독립 분류기 금지.
- 순수 분석은 같은 입력에서 같은 결과. 시간적 안정화가 필요하면 소유자,
  기준, 무효화 조건을 명시하며 UI 로컬 sticky label로 사실을 가리지 않음.
- 기록 권한 철회/제외는 이전 표시 유지보다 우선.

## 8. 5단계: 실제 화면과 안정성

- 목록과 Intel의 역할을 구분하고 중복 숫자/정책 편집을 줄인다.
- 대표 설명·시각화·근거는 같은 revision으로 함께 갱신한다.
- 같은 정책의 갱신 중 준비된 화면·포커스·스크롤·펼침 상태를 유지한다.
- 선택 사이트의 늦은 응답, 저장 초안, 실패·재시도 계약을 보존한다.
- 기존 선택 사이트 상세 cache와 in-flight 합류를 유지한다.
- 화면 미선택 상태에서 상세 분석을 반복하거나 모든 목록 항목에 full
  analysis를 실행하는 회귀가 없는지 비용을 확인한다.
- Zen/Matrix, desktop/narrow, 여러 coverage 상태와 긴 도메인을 확인한다.
- named QA는 해당 skill과 canonical QA control plane으로 수행한다.
- 관련 제품 문서·경계 문서·계약 테스트와 개발 dist를 함께 갱신한다.

제품 판단 기준은 사용자가 짧은 시간 안에 자기 사용 특징과 그 근거를
이해하는가이다. 테스트 PASS는 이 이해도 평가를 대체하지 않는다.

## 9. 6–7단계: 심화 모델과 점수

심화 후보는 1단계에서 확인한 전체 모델 inventory를 기준으로 재정렬한다.
시간대 반복성, 전환 경로, background context, feed 소비, intervention
결과가 각각 어떤 질문에 답하는지 먼저 정하고 통합 여부를 결정한다.

종합 점수는 별도 채택 결정이다. 다음이 닫히기 전에는 신규 위험도를
제품 전면에 노출하지 않는다.

- 숫자가 압축하는 대상과 그 대상의 한계.
- 개인 변화와 절대 행동 형태, 목표 불일치의 분리.
- correlated signal 중복, 권한/등록/목표 변경에 대한 불변 조건.
- 샘플 부족을 낮은 위험도로 보이게 하지 않는 품질 표기.
- 유효 사례·반례·경계 민감도와 사용자 해석의 일치.
- 기존 점수 소비처와 보호 실행에 대한 영향.

진단 전용 비교는 허용되지만 두 점수를 번갈아 정본으로 읽는 대체 경로를
만들지 않는다. 새 점수가 불필요하면 보류 사유를 기록하고 해당 단계를 닫는다.

## 10. 변경·검증·종료 관리

- 각 구현 묶음: 코드 → owning 문서/계약 → 집중 검증 → 필요한 named QA/build.
- 현재 작업 트리의 다른 변경을 보존하고 변경 소유 범위를 기록한다.
- 되돌림은 해당 변경 diff를 기준으로 수행하며 사용자 기록/설정을 지우지 않는다.
- 저장 schema 변경이 있는 묶음은 데이터 호환성 결정을 별도 기록한다.
- 미래 임계값은 계획 문서에 숫자를 먼저 박지 않고, 근거·평가와 함께 정한다.
- 새 기능이 기존 런타임 동작을 바꾸면 그 소비처 검증을 같은 묶음에 포함한다.
- 종료 시 완료된 계획은 archive 규칙에 따라 보존하고 현재 결정은 owning
  Active 문서로 옮긴다. 이 문서가 두 번째 구현 정본으로 남지 않게 한다.

## 12. 선행 결함 수정과 남은 작업

이번 묶음의 상세 결과는
[경계 수정 보고서](../../reports/site-intel-analysis-boundary-repair-2026-09-14.md)에
기록한다. 최초 감사와 순수 재현 JSON은 수정 전 증거로 보존한다.

반영한 경계:

- 최종 분류·점수·해석 객체를 intel/vector/facts 입력에 다시 넣으면 오류를 낸다.
  insights import 그래프에서도 상류 → 최종 판단의 역방향 의존을 금지한다.
- feed detector pressure/interrupt 카운터는 역사 진단에만 남기고 분석 facts에서는
  제외한다. 큰 카운터를 주입해도 전체 facts/profile 결과가 같아야 한다.
- private featureVector 캐시를 제거했다. 내부 facts와 공개 facts의 재계산이
  같은 경로를 사용하며, 원본과 복제 벡터가 다른 판단을 만드는 통로가 없다.
- missing/observed-zero를 엔진에서 구분한다. missing은 null 점수·등급과
  insufficient_data이며, 낮은 위험이나 활동 없음으로 변환하지 않는다.
- FULL 행동 비교는 달력일로 정렬하고, 목표 청구는 별도 활동일 context로 유지한다.
  0인 목표 사용량을 달력일의 양수로 대체하지 않는다. 목표 파생 수치도 검증한다.
- 개입의 제시 자체는 응답이 아니다. 실제 eligible 응답이 있어야 응답 모드를 쓴다.
- 엔진의 terminal interpretation이 대표 문장과 근거 ID를 정한다. 두 테마 경로의
  재선택·confidence 대체 판정을 제거했다. 혼합 점수는 진단 전용으로 명시한다.

남은 일은 경계 결함과 구분한다. 목표가 일부 행동 profile의 강도에 섞여 있는 점,
관측 marker만으로는 연속 기록 범위를 알 수 없는 점, 목적·의도에 대한 근거가
부족한 점은 아래 모델 작업의 대상이다. 이번 수정으로 모델 전체가 검증된
행동 과학 도구가 되었다거나 모든 편향이 제거됐다고 주장하지 않는다.

| HabitConsistency | 사용일·규칙성·반복 확인/압력 문맥 | 자주 쓴다는 사실과 원치 않는 습관을 구분. 날짜별 반복성을 누적 peak와 구분 | 매일 일정한 공부/음악, 주말만 정기 사용 |
| SustainedBlock | 세션/시간대 집중, 목표·focus 문맥 | 실측 긴 세션과 hourly proxy의 주장 상한 유지. 종료와 이후 재진입 정보의 필요성 평가 | 한 시간 안의 독립 짧은 세션들, 자료를 보며 집중한 작업 |
| NightPressure | 고정 야간 시간대와 사용 강도 | 야간이라는 기술적 사실을 수면 방해로 단정하지 않기. 개인 반복 창과 연결 시 충분한 기록 필요 | 야간 근무, 여행, 단발성 심야 사용 |
| RoutePressure | 전환 edge·출입·반복 경로의 독립 family | 이벤트 순서가 있는 loop와 기간 합산을 구분. root/subdomain 소유권 보존 | 여러 번의 독립 A→B 이동, 같은 앱 하위 호스트 이동 |
| ControlledBrief | 짧은 사용과 낮은 압력, goal·intent 맥락 | 관측 부족을 절제·통제 성공으로 칭찬하지 않기. 실제 종료·짧은 체류가 있어야 제한된 묘사 | 기록 직후 0분, 빈 방문, 미허용 정밀 기록 |
| Immersion | 세션 길이·집중 비중·navigation continuity·개인 lift | 오래 이어짐과 원치 않는 흡수를 구분. 시간·depth·background의 중복 가산 검토 | 긴 강의/문서 작업, 백그라운드 음악 |
| SessionDepth | max/long-session rate와 개인 p75/p90·robust z | 평균·최대·분포를 구분. baseline만으로 깊은 몰입을 단정하지 않기 | 드문 한 번의 긴 세션, 잘린/불완전 세션 |
| InterventionOutcome | eligible continue/leave·후속 reentry·recovery | 제시만으로 모드 변경되는 경계는 수정. 다음은 실제 응답 분모·관찰 지연·censoring과 효과별 범위 검증 | 제시만 있고 응답 없음, 추적 종료 후 재진입 미관측, 강제 닫기 |
| BackgroundResidency | media·linger·stale 탭 시간 | 탭 열림/오디오 재생/주목을 분리. active 사용과 합산해 사람의 시간이 늘어나지 않게 함 | 음악 탭, 참조 자료 대기, 여러 백그라운드 탭 |
| ContentFlow | advance/skim/scroll을 하나의 feed_progression family로 취급 | 판단 카운터는 분석 입력에서 제거. 독립 두 번째 근거가 없으면 feed_loop를 계속 닫아 둠 | 큰 scroll 카운터, 장문 빠른 탐색, 세 alias의 동시 증가 |
| TabContext | new/duplicate/high-open/max-open 탭 단서 | 누적 갯수와 짧은 시간의 확산을 구분. 같은 사건이 checking과 tab 증거를 중복 지지하는지 검토 | 정돈된 참고자료 탭, 브라우저 세션 복원, 사이트 내부 팝업 |

각 profile 검토의 산출물은 **주장 → 필요한 사실 → lineage → 반례 → 품질/보류
조건 → calibration 영향 → 소비처 영향**의 한 장짜리 표와 독립 기대값 fixture다.
수치가 낮거나 높은 예만 만드는 대신, 표현을 해서는 안 되는 사례를 먼저 만든다.

### CLSE 및 다른 모델의 별도 경계

CLSE baseline의 `buildCLSEBaselineObservation()`은 원본 bucket의 active
exposure, tab switch/nav/seek rate와 scroll volatility를 읽는다. 서비스는
완료 bucket을 분석한 뒤 같은 원본 bucket으로 baseline을 갱신하며 최종
aggression score를 baseline sample로 사용하지 않는다. 실제 관찰로 개인
참조가 적응하는 것은 허용한다. 개입 중 학습 admission이 제한되는 정책은
표본 선택 편향 관점에서 별도 평가할 대상이다. 이번에 그 정책을 바꾸지 않는다.

Consumption memory와 전체 pressure/goal ledger는 Site Pull 분류의 입력
대체물이 아니다. 모델 의미와 시간 단위가 다르므로 임의 합산하지 않는다.
CLSE 진단 결과를 향후 Intel에서 보여주더라도 terminal evidence로 소비하며,
Site Pull의 행동 사실이나 baseline으로 되먹이는 경로를 만들지 않는다.

## 14. 후속 실행 순서와 채택 기준

1. **의미·반례 묶음 확정:** 기록 범위별 capability와 공통 observation/period
   envelope, 목표와 행동의 반사실 사례를 먼저 정한다. 화면은 대표 사례의
   문장과 근거 배치만 시안으로 검토한다.
2. **기초 4층 교정:** TimePressure → SessionDepth/SustainedBlock → Checking
   순으로 다듬는다. 자료 손실/분모/목표 혼합을 해결한 뒤 가중치를 건드린다.
   단순 강도 증가, 복제 alias, 목표 변경에 대한 불변성과 단조성을 검증한다.
3. **문맥층 교정:** Trend/Habit/Night/Background/ControlledBrief/Immersion을
   개인 반복성과 현재 상태에 맞춰 분리한다. ‘많다’, ‘길다’, ‘반복된다’의
   사실과 ‘원치 않는다/위험하다’의 판단을 같은 것으로 취급하지 않는다.
4. **순서·결합층 교정:** Route/Tab/ContentFlow/Intervention을 검토한다.
   새 사건 정보가 실제로 필요할 때만 typed 저장·수집 계약을 확장한다.
   단순히 더 강한 분류를 만들기 위해 카운터나 수집 범위를 늘리지 않는다.
5. **출력 계약과 첫 Intel 완성:** 엔진이 선택한 한 가지 finding, 수치·범위가
   있는 1–2개 근거, 필요한 한 개의 시각화로 구성한다. 기준·한계는 펼쳐본다.
   추천·사이트별 교정은 전제가 아니다. Zen/Matrix named QA와 갱신 연속성,
   keyboard, 기록 부족 및 실패 상태를 확인한다.
6. **종합 점수 결정:** 의미가 검증된 각 축을 먼저 사용하고, 하나의 수치가
   실제 판단을 더 잘 돕는지 평가한 뒤 채택/보류한다. 진단 점수를 자동으로
   제품 점수로 승격하지 않는다.

공통 평가 매트릭스: observed-zero/missing/partial/off/protected-only,
기본/정밀 권한 차이, reset-hour/자정, 실측/proxy, 목표만 변경, 개인 기준만
변경, 같은 사건 alias 증가, 개입 제시만 증가, 늦은 응답과 사이트 전환.
평가 결과에 따라 gate를 보수적으로 닫을 수 있어야 하며 모든 사례에서
반드시 분류를 내는 것을 성공 기준으로 삼지 않는다.

## 15. 기초 모델 교정 반영 (2026-09-14)

현재 모델은 `site-pull-release-v3`다. 14절의 기초 교정을 다음 범위로 완료했다.
상세 근거와 검증은
[`기초 모델 교정 보고서`](../../reports/site-intel-foundation-model-correction-2026-09-14.md)에 남긴다.

| 대상 | 반영한 교정 | 남은 검토 |
| --- | --- | --- |
| TimePressure | 목표 초과 채널·목표 유무 confidence 보너스 제거. 현재 사용량과 개인 상승만 해석. 주간 기준 부족 시 배수는 null | 시간대별 진행도·부분 관측 적격성, 안정적 고사용의 기술적 표현 |
| Session source | 4개 evidence consumer의 현재 세션 projection을 한 소유자로 통합. 실측 0/과거 세션/추정치를 섞지 않음 | 관측 marker만으로 알 수 없는 측정 범위, 세션 잘림 여부 |
| SessionDepth | 세션 지표 자체의 표본·confidence 사용. empirical percentile과 계산용 reference 구분. 0 기준 배수 제거 | 최대 한 번의 증가와 분포 전체 변화의 의미 차이 |
| SustainedBlock | 최대 실측 세션만 연속 길이로 사용. 3시간 합은 별도 집중도. 목표의 영향 제거 | 길게 이어짐을 집중 성공·흡수로 해석하는 문맥의 타당성 |
| Checking | 복귀·전환·경로의 중첩 합산과 곱 보너스 제거. 개인 anomaly도 같은 family 안에서 최대값 사용. 작은 분모에 count gate 적용 | 시간 순서·동시성의 실제 증명, 방문 밀도 및 context 신호 간 잔여 의존성 |
| 소비 경계 | Immersion이 교정된 연속 길이를 hourly 합으로 되돌리는 우회도 제거. detector 요구조건·threshold inventory·UI의 배수 서식 동기화 | ControlledBrief/Immersion 자체의 목적·가치 판단은 다음 단계 |

기존 정상 검출 사례의 기대 패턴을 유지하면서 잘못된 주장에 대한 반례를 추가했다.
점수 하락을 기존 숫자에 다시 맞추기 위해 전체 가중치나 임계값을 재팽창시키지 않았다.
단, 중복 억제는 사건 ID 기반 완전한 중복 제거가 아닌 보수적인 상한이다.

기초 교정 당시 다음 단계는 **문맥층 교정**으로 정했다. ControlledBrief/Immersion의 가치 판단부터
분리하고, Trend/Habit/Night/Background를 관측 범위와 반복성에 맞춰 검토한다.
그다음 Route/Tab/ContentFlow/Intervention의 시간 순서와 복합 판정의 품질을
다룬다. UI 리디자인과 종합 점수 채택은 이 검토 뒤에 진행한다.

## 16. 문맥층 교정 완료와 다음 작업 (2026-09-15)

`site-pull-release-v4`에 반영했다. 현재 정본은
`docs/architecture/repository/site-pull-pattern-boundary-map.md`의 Context model
contract다. 새 저장·수집·개인 기준 DTO 없이 기존 사실의 해석을 교정했다.

| 부분 | 이번 교정 | 남은 한계 |
| --- | --- | --- |
| ControlledBrief | 현재 실측 짧은 세션만 허용. 목표·조용한 맥락으로 통제 성공을 판정하지 않음 | 의도·종료 성공은 수집하지 않음 |
| SustainedBlock / Immersion | 실측 연속 길이의 강도와 맥락 분리. 동일 날짜 탐색·복귀는 중복 최대값, 가치 판단 중립 | 같은 세션 안의 순서·연관성은 증명하지 않음 |
| Habit | 관측 날짜·연속 사용·분량 중심. pooled hourly peak, 현재 목표·확인 압력 및 Trend 판정을 습관 근거로 재사용하지 않음 | 습관의 자동성이나 매일 같은 시간의 반복은 미판정 |
| Night | 고정 시각 구간의 사용량. 평균 분모·nullable 위치 교정, 주간 합계의 반복 밤 판정 제거 | 개인 수면 시각과 날짜별 심야 반복 미판정 |
| Background | facts.behavior 정본, 겹치는 채널의 강도 최대값. 3일 이상 날짜별 근거가 있어야 반복 상태 | 최대값도 고유 경과 시간·주의력은 아님 |
| Trend | 비교 7칸 충족, 단일 급등의 무조건 제외, 정본 trajectory confidence 상한 | 증가의 이유·좋고 나쁨은 판정하지 않음 |

패턴 ID는 소비 계약을 위해 유지한다. 중립적 표현, feedback role, 적용 가능한
근거 서식과 threshold/decision audit를 함께 갱신했다. UI가 임의로 재분류하지
않으며 분류·해석 출력은 원시 사실·통계·개인 기준에 되돌려 쓰지 않는다.
상세 검증은 `reports/site-intel-context-model-correction-2026-09-15.md`에 기록한다.

다음 순서는 **사건 순서와 결합 모델 교정**이다.

1. Route: 방향, 재방문 시간 구간, 동일 전환의 중복과 분모를 확인한다.
2. Tab / ContentFlow: 탭 전체 상태와 선택 도메인의 사실을 분리하고, 하나의
   물리 사건에서 나온 별칭을 독립 근거로 세지 않도록 검증한다.
3. Intervention: 노출·계속·떠남·복귀의 정책별 모집단과 평가 가능 범위를
   재검토한다. 선택했다는 사실과 의도 실패를 분리한다.
4. Composite / decision quality: 같은 날 함께 있다는 것과 시간 순서가
   증명된 것을 구분하고, 중복 가중·confidence 상승·억제의 반례를 검증한다.
5. 위 검토가 끝난 뒤 Intel의 대표 문장·근거·선택지 구성을 확정한다. 종합
   사용자 점수는 별도의 검증 자료와 개인 기준 정책이 갖춰진 뒤 결정한다.

## 17. 사건·모집단 및 복합 판정 교정 (2026-09-15)

Route / Tab / ContentFlow / Intervention과 Composer / DecisionQuality의
소유권 및 의미 교정을 구현했다. 모델은 `site-pull-release-v5`다.

1. 경로 입력을 facts로 한정하고 조회 소유자의 방향을 전달한다. 7일 슬롯,
   별도 주간 기록, 제한된 edge projection의 의미를 보존한다.
2. 탭 판정을 한 소유자로 모으고 가짜 분모와 브라우저 전체 탭 가산을 제거한다.
   피드·스크롤 중복 채널은 최대값으로 제한한다.
3. 개입의 재방문/떠나기 모집단과 선택 기간을 통일한다. 중첩 구간 가산,
   계속 이용의 실패 취급, 후속 관측이 없는 성공 추정을 제거한다.
4. Composite는 현재 관측 차원의 동시 출현 또는 단일 계열 강도 요약이다.
   출력에서 원시 근거를 재구성하지 않고 별칭 개수로 신뢰도를 올리지 않는다.
   DecisionQuality도 문자열 수로 근거 품질을 변경하지 않는다.
5. 노출 이전 응답은 저장 소유자가 거부하며, 날짜 경계를 넘는 응답은 원래
   노출 모집단에 귀속됨을 검증한다. 새 저장 키/수집/평균 DTO는 없다.

구현·검증 결과: [사건·복합 판정 보고서](../../reports/site-intel-sequence-composition-correction-2026-09-15.md).

- 진짜 순서/교정 효과/의도 추정이 필요해지면 별도 설계에서 사건 연결,
  후속 관측 성숙도와 정책 변경 시 모집단을 정의한다. UI 요구만으로
  분류 출력을 원시 입력이나 개인 기준으로 되돌려 쓰지 않는다.


## 18. Intel 출력 계약과 소비 연결 (2026-09-15)

기존 terminal interpretation을 v2로 확장했다. 41개 패턴의 대표 문장 키,
시간/횟수/일수, 원 근거 필드, 기간, 계열과 개입 모집단을 명시한다.
대표 근거는 같은 주장의 관측값 최대 두 개이며, 펼침 항목과 정책 항목의
참조도 도메인이 지정한다. 공통/Zen 소비자는 이를 서식화한다.

- no-record / observed-zero / activity-without-primary 상태를 분리했다.
- 0을 숨기거나 미확보 값을 0으로 만드는 chip 코드를 제거했다.
- UI의 headline 매핑·근거 필드 선택·합산·정렬을 terminal 소유로 옮겼다.
- 날짜/품질/출처 변조와 다른 패턴의 근거 삽입은 소비 계약에서 거부한다.
- 일일·주간·개인 기준·개입의 기간을 섞지 않는다. trajectory의 정확한 날짜
  범위는 현재 owner가 공개하지 않으므로 명시적 미공개로 남겼다.
- 실제 원시 시나리오 8개에서 문장과 근거를 생성했다. 이 자료는 제품
  이해도 검증을 대신하지 않으며 가상의 관측임을 명시한다.

이 단계는 Intel reading contract v2로 완료했다. 현재 정본은 설명 키를 추가한
Site Pull 경계의 Intel reading contract v3와 사이트 탭 PRD다.
결과는 [출력 계약 보고서](../../reports/site-intel-reading-contract-2026-09-15.md),
사례는 [한·영 출력 예시](../../reports/site-intel-reading-contract-cases-2026-09-15.json)에 기록한다.

다음 단계에서는 이 계약을 그대로 소비하는 압축된 시각화를 설계한다.
긴 세션 / 반복 접속 / 혼합 사용 / 부족한 기록에서 무엇을 이해할 수 있는지
확인하고, 그 결과를 바탕으로 Intel 내부 배치를 재설계한 뒤 Zen/Matrix의
desktop/narrow 명명된 QA를 수행한다. 근거가 부족하다는 이유로 새 점수나
추천으로 빈 공간을 채우지 않는다.


## 19. Intel 읽기 화면 재설계 (2026-09-15)

이번 단계는 대표 문장과 같은 주장의 근거 최대 두 개를 한 장면으로 묶는다.
범위 → 문장 → 수치/허용된 비교 → 근거와 관측 내역 → 기존 액션 순서다.
Zen과 공통 패널의 중복된 조립을 없애고 공통 읽기·표시 모델을 사용한다.
완료된 과거 비교·오늘 달력일·활동일 정책의 의미는 서로 바꾸지 않는다.

기본 화면의 일별/시간대 그래프와 반복 통계 행을 제거한다. 일별 기록은
펼침 영역의 중립적 그래프와 표로 남기고, 반복 시간대는 정본에서 승인된
경우만 표시한다. 사건 순서·위험 점수·교정 성공을 새로 추정하지 않는다.

표시 모델/공통 컴포넌트 → 주요 사례 → 상세/액션 → 계약 및 개발 빌드를
구현했다. 모델 v5와 interpretation v2를 유지한다.
named intel-reading은 원시 fixture를 실제 모델에 통과시킨 표시 검증이며,
실제 기록 수집이나 이해도 검증의 대용이 아니다. recording-refresh는
별도로 실제 주기 갱신과 권한 변경을 검증한다.

관련 13개 파일의 158개 테스트와 SSOT/조회/테마/번역 경계 검사가 통과했다.
권한 철회 중 대기 객체의 분석 투영 오류도 Intel 승인 경계에서 수정했다.
명명된 QA의 실행별 결과·실패 원인·남은 Zen 좁은 화면의 메인 부팅 문제는
[읽기 화면 구현·검증 보고서](../../reports/site-intel-reading-surface-2026-09-15.md)에 기록한다.
