# 분재 습관 피드백과 활성화 회복 설계

- Status: Proposed
- Owner: product / stats domain / zen theme architecture
- Last validated against code: 2026-10-11
- Path policy: planning-allowed
- Decision needed: 합의한 기준에 대한 최근 준수를 활성화의 단일 의미로 채택하고, 관측 증거와 일일 마감 계약을 먼저 갖춘 뒤 수치와 표현을 검증한다.

분재는 사용자를 평가하는 성적표가 아니라, 자신이 정한 사용 기준과 실제 행동의 관계를
읽을 수 있는 피드백이다. 권장 뼈대는 **누적 성장, 최근 활성화, 관측의 확실성을 분리**하고,
활성화에는 확인된 기준 준수와 초과만 반영하는 것이다. 프릭션 취소 횟수는 보상 화폐로
만들지 않는다. 의도대로 계속하기도 정상일 수 있고, 개입이 덜 필요해지는 사용도 좋은 결과다.

이 제안은 다음 구현의 설계 기준이다. 현재 점수식과 저장 계약을 변경하지 않는다.
현재 권위는 [점수 원장](../../domains/stats/score-ledger-architecture.md),
[통계 엔진](../../domains/stats/stats-engine-baseline.md),
[분재 생명 모델](../../architecture/themes/zen/zen-bonsai-vitality-growth-spec.md)에 있다.
문헌의 결과, 아래 제품 결정, 수치 시뮬레이션은 서로 다른 종류의 근거다.

## 1. 평가 대상과 채택할 원칙

평가 대상은 **관측 가능한 범위 안에서 사전에 합의한 기준에 대한 최근 준수 상태**다.
시간이 짧다는 사실을 집중력, 의지력, 생산성, 정서적 건강이나 의도성 자체로 해석하지 않는다.
휴식과 오락도 정당한 목적이다. 현재 명시적 시간 기준으로 알 수 있는 범위를 먼저 구현하고,
계획한 종료나 특정 시간대의 비사용 같은 다른 약속은 별도 계약이 생겼을 때 확장한다.

1. 기준은 사용자가 수락한다. 개인 과거 사용량은 설명과 목표 제안에만 쓰고 자동으로 목표를 낮추지 않는다.
2. 기준 안에서는 더 적게 쓸수록 더 높은 보상을 주지 않는다. 유지 가능한 준수 자체로 충분하다.
3. 프릭션 노출, 대기 완료, 계속하기, 떠나기는 그 자체로 선악 판정하지 않는다.
4. 실제 초과는 관측 범위가 부분적이어도 사라지지 않는다. 확인할 수 없는 나머지는 추측하지 않는다.
5. 관측 부족은 활성화의 회복이나 손상을 발생시키지 않는다. 충분히 관측된 비사용과 기록 부재를 구분한다.
6. 한 활동일 결과는 한 번만 반영한다. 홈 방문, 렌더 횟수, 사이트 수, 프릭션 수가 회복 속도를 늘리지 않는다.
7. 활성화가 낮아져도 누적된 나무의 구조와 개체 정체성은 보존한다. 회복은 되돌릴 수 있는 생기 표현을 바꾼다.

## 2. 연구가 지지하는 범위

아래 연구는 설계의 방향을 판단하는 근거다. Entropy의 효과나 특정 점수식의 타당성을
입증하지 않는다. 스마트폰 앱 결과를 브라우저 확장에 옮길 때에는 관측 범위와 개입 방식의
차이가 남는다. 특히 시간 감소, 의도와의 일치, 통제감, 개입 부담은 별도 결과로 평가한다.

### 이름만으로 재사용하면 안 되는 기록

- `left`는 떠나기 선택의 근거이지, 실제 foreground 소비 종료와 그 뒤의 비재진입을 모두 보증하지 않는다.
- 현재 `reenteredWithin5m/30m`는 continue 승인 후 목적 페이지 복귀를 기록한다. leave 뒤의 재방문 지표로 재사용하지 않는다.
- `escape_closed`는 우회 탐지 뒤 탭 닫기를 요청하는 흐름에서 기록된다. 자발적 종료나 실제 닫기 성공의 증거가 아니다.
- 현재 `policyContextHash`에는 interaction 식별자가 전달된다. 이름과 달리 재현 가능한 설정 snapshot hash로 취급하지 않는다.
- 확정 foreground 구간은 존재하지만 시간당 32구간 제한과 절단이 있다. 구간 부재는 사용 0이나 휴식의 증거가 아니다.
- collection의 현재 admission과 처음/마지막 수집 시점은 하루 전체 관측 연속성을 보증하지 않는다.

[InterventionEffectStore](../../../src/platform/storage/internal/indexeddb/stores/InterventionEffectStore.js),
[통계 엔진의 확정 구간 계약](../../domains/stats/stats-engine-baseline.md)을 따른다.
정확한 노출별 결과와 관측 연속성의 조회 계약을 갖추기 전에는 성공 판정을 보류한다.

## 4. 입력과 관측 상태

판정 단위는 명시적인 활동일의 **사용자 수락 기준과 그 범위의 확정 기록**이다.
현재 브라우저·프로필·동의 범위 밖의 활동은 평가하지 않는다. 다른 기기에서 덜 썼는지,
오프라인에서 집중했는지, 사용 목적이 무엇인지는 로그만으로 알 수 없다.

| 입력 | 최소 v1 처리 |
| --- | --- |
| 사전에 수락한 양의 시간 예산과 확정된 사용량 | 준수·초과의 주 입력. 전역 기준과 사이트 기준이 겹쳐도 이중 감점하지 않음 |
| 명시적 떠나기, 실제 종료, 후속 관측 | 별도의 조절 행동 기록. 확인 수준을 구분하고 활성화 가산점으로 사용하지 않음 |
| 프릭션 노출·대기 완료·continue·강제 종료 | 사실과 맥락을 표시하되 성공/실패 점수로 변환하지 않음 |
| 탭 전환, 스크롤, 재방문 빈도, 사이트 종류 | 기본 중립. 명시적으로 수락한 다른 종류의 기준이 생기기 전에는 감점하지 않음 |
| 개인 과거 사용량 | 기준 제안·회고의 비교 자료. 기준 변경은 명시적 수락을 거침 |
| 선택적 통제감·후회·부담 응답 | 향후 설계 평가 자료. 점수 보상이나 자동 정책 조정에 바로 사용하지 않음 |

사용량 입력은 metric과 scope를 함께 가진다. 현재 전역 점수의 사용량은 전체 브라우저 시간이 아니라
보호사이트의 charged active usage다. 새 판정에서도 예산과 사용량의 대상 범위를 맞춘다.

관측은 최소 다음 상태를 구분한다.

- **complete:** 합의한 범위와 시간 경계의 필요한 기록이 닫혔고, 누락 여부를 판정할 근거가 있음.
- **partial:** 일부 기록만 있으나 실제 사용량의 하한과 그 출처는 확인할 수 있음.
- **unknown:** 유효한 기준·시간 경계에 연결되는 판단 근거를 확보하지 못함. 손상·모순·계약 위반은 별도 error로 노출.
- **not_applicable:** 수락한 평가 기준이 없음. 100점이나 완전한 생기로 치환하지 않음.

유효한 기준·기간에 대해 확정된 사용 하한이 있다면, 나머지 관측의 연속성을 확인하지 못해도
partial로 판단한다. 전체 관측 부족을 이유로 확인된 특정 위반을 unknown 속에 묻지 않는다.
유효성은 규칙별로 판정한다. 지원하지 않는 규칙 하나가 있어도 다른 유효 규칙의 확정 위반을
지우지 않으며 전체 상향 판정만 보류한다. 계약 오류는 코드와 범위를 별도로 노출한다.

비사용은 별도 행동 내용이다. complete 범위에서 사용 0을 확인했다면 시간 예산의 비위반으로
유지·회복에 반영할 수 있다. 이는 의도적인 절제의 증명이나 금욕 보너스가 아니다.
단순히 row가 없거나 브라우저·권한·수집이 꺼져 있었던 기간을 complete로 만들지 않는다.
이 구분이 없으면 나무를 회복시키기 위해 일부러 보호 사이트를 방문해야 하는 유인이 생긴다.
현재 기록만으로 complete 비사용을 인증할 수 없다면 unknown으로 남긴다.

판정의 근거는 사용량의 증명 가능한 구간 `[u_lower, u_upper]`로 설명할 수 있다.
모든 기준의 상한이 목표 이하이면 비위반이 확정되고, 하나라도 하한이 목표를 넘으면 위반이 확정된다.
기록 0은 보통 하한이 0이라는 뜻이며 상한도 0이라는 보증이 아니다. 구간의 상한을 새로 수집하거나
추정하라는 뜻은 아니며, 기존 관측 계약이 제공하지 못하면 unknown을 유지한다.

관측 충분성의 분모는 **수락한 기준의 관측 범위**다. 업무 사이트 수집을 추가했다고 보호 사이트의
확인된 위반이 사라져서는 안 된다. 더 넓은 수집 동의를 높은 점수의 조건으로 만들지 않는다.

## 5. 최소 수학 모델

### 5.1 지표의 역할

- `A` 활성화: 최근 활동일들의 합의 기준 준수 상태. 범위 `[0,1]`.
- `R` 조절 행동: 확인된 선택과 결과의 별도 설명. `A`의 가산점·회복 속도 보너스가 아님.
- `Q` 관측 상태: 범위·완전성·마지막 확인 시점. `A`와 혼합하지 않는 구조화된 정보.
- `S` 구조 성장: 누적 공개·성숙 정책. `A`와 독립적이고 회복을 위해 되감지 않음.
- `B` 개화 표현: `A`, 계절·개체 특성 등 명시적인 표현 정책의 출력. 별도의 습관 점수가 아님.

오늘의 기준 준수 결과와 최근 `A`는 다를 수 있다. 오늘은 이미 개선됐지만 최근 상태의 회복은
진행 중일 수 있다. 차이를 시간 범위로 설명하고, 서로 다른 공식을 모두 현재 건강이라고 부르지 않는다.
현재 숫자 점수를 유지할 경우 별도 레거시 건강 지표로 남기지 않고 새 일일 판정의 설명으로 재정의한다.

### 5.2 연속적인 초과 심각도 후보

시간 예산 종류에 한정한 최소 후보식이다. `g_i > 0`은 사전 수락된 예산, `u_i >= 0`은
그 활동일의 확정 사용 분, `tau > 0`는 짧은 예산의 상대 초과가 과대 반응하지 않도록 하는 분 단위 척도다.
적용 가능한 수락 기준이 하나 이상일 때만 T를 산출한다. 기준이 없으면 not_applicable이며 빈 집합의
기본값을 좋은 결과로 만들지 않는다.

```text
excess_i = max(0, u_i - g_i)
V_i = clamp(excess_i / (g_i + tau), 0, 1)
V = max_i(V_i)
T = 1 - V
```

기준 안에서는 `T=1`이며 5분과 19분을 썼다는 이유로 20분 기준의 보상이 달라지지 않는다.
정상 사이트를 추가하거나 같은 기준을 복제해도 최악 초과가 희석되지 않는다. 전역/사이트 기준의
겹침도 이중 합산하지 않는다. 기존 1.5배 경계 같은 값의 불연속이 없다.

`max`는 최소 v1의 보수적인 선택이다. 여러 약한 초과가 하나의 약한 초과보다 더 무겁게 반영되지는
않으며, 포화 이후 추가 초과는 활성화를 더 내리지 않는다. 원래 초과량과 모든 위반 항목은 설명에
보존한다. 여러 기준의 균형을 더 다루려면 희석·중복 문제를 다시 검증한 별도 집계 계약이 필요하다.

`tau`는 허용 시간을 늘리는 grace가 아니다. 초과는 `u>g`부터 존재하며 기울기만 조정한다.
0분의 절대 금지, 시간대 회피, 세션 종료 약속은 다른 규칙 종류이므로 이 식에 억지로 넣지 않는다.
입력에 규칙 종류와 의미가 없으면 추정하지 않고 해당 판정을 unavailable로 노출한다.

### 5.3 회복과 악화

```text
complete: A_next = A + alpha * (T - A)
partial:  A_next = min(A, A + alpha * (T_upper - A))
unknown / not_applicable: A_next = A
```

`0 < alpha <= 1`. partial의 관측 사용량이 실제 사용의 하한일 때, 그 기록으로 계산한
`T_upper`는 실제 준수 품질의 상한이다. 이미 확인된 큰 초과는 하향 근거로 쓰되, 누락된
나머지를 준수로 가정해서 상향하지 않는다. 사실의 손상·시계 오류 등으로 하한조차 보장할 수 없으면
partial이 아니라 unknown/error다. 완전한 자료가 뒤늦게 도착하면 순서대로 재계산하며 이 partial
갱신 위에 같은 하루를 다시 더하지 않는다.

이 모형의 회복은 벌점 상쇄가 아니라 **최근 상태가 개선된 기록을 따라가는 것**이다.
따라서 활성화가 매우 낮은 사람은 초과가 남아 있어도 이전보다 훨씬 덜 초과한 날에 일부 회복할 수 있다.
그날의 위반을 준수로 바꾸거나 숨기지는 않는다. 반대로 높은 활성화에서는 같은 날이 소폭 하락을 만든다.
모든 미세한 초과는 반드시 하락하고, 경계의 준수는 즉시 회복하며, 경계는 연속이라는 세 조건을
모두 요구하지 않는다. 여기서는 연속성과 최근 상태라는 의미를 택한다.

unknown 기간에는 자동 중립 drift, 숨은 부채, 무한 catch-up 손상을 두지 않는다.
관측 신뢰도와 마지막 확인 시점만 갱신한다. `neutral + confidence*(A-neutral)`로 표현을 섞으면
관측 부족만으로 낮은 A가 좋아 보일 수 있으므로 금지한다. 활성화의 해석과 관측 부족의 표시는 분리한다.

당일 반응이 필요하면 마지막 확정된 A를 고정한 채 위 partial 식으로 미리보기를 재계산한다.
확인된 초과는 바로 보이되 이벤트마다 A를 누적 적분하지 않는다. 오전의 사용 0이나 새로고침으로
회복하지 않으며 상향 회복은 유효한 활동일 결과가 닫힐 때 한 번 확정된다. 실시간 원본을 읽어야
한다면 기존 stats의 runtime-overlay 금지를 우회하지 않고 명명된 query 계약을 추가한다.

새 모델의 명시적 초기화에서는 `A=A_seed`, `judged=false`로 시작한다. A_seed는 버전이 있는
제품 초기 상태이며 사용 기록으로 추정한 점수가 아니다. 첫 판정 전 장식용 나무의 중립 모습도
점수로 표시하지 않는다. 첫 complete뿐 아니라 첫 partial의 확인된 위반도 같은 초기 상태에서
위 식을 적용하고 이후 결과를 순서대로 반영한다. 나중의 첫 준수일에 A를 1로 재설정해서 과거의
확정 위반을 지우지 않는다. 실제 판정 수준과 자료가 적다는 정보를 함께 표시한다.

A_seed는 튜닝 대상이며 아래 시뮬레이션은 이미 판정된 A에서 시작한다. 기존 canonical state가
손상되거나 누락된 경우를 새 설치로 간주해 이 초기값으로 복구하지 않는다. 그 경우는 명시적 error다.
judged는 첫 유효 준수 판정 또는 확인된 초과가 반영될 때 참이 되며, 관측 수준은 계속 Q로 구분한다.
이 초기화와 첫날 표현의 적절성은 출시 전 사용성 검토 대상이다.

### 5.4 수치 민감도와 검증 범위

`alpha=.25`, `tau=10분`은 **합성 시나리오를 읽기 위한 가정값**이며 배포 기본값이 아니다.
회복 일수는 달력일이 아니라 유효한 닫힌 활동일 수로 센다.

| 시나리오 | 가정값에서의 결과 |
| --- | --- |
| A=.30에서 T=1인 결과가 이어짐 | 1회 .475, 4회 .779, 7회 .907 |
| A=.80에서 T=0인 결과가 이어짐 | 1회 .600, 2회 .450, 3회 .338 |
| A=.80에서 한 번 T=0, 다음 T=1 | .600 → .700; 한 번의 실수 뒤 회복 가능 |
| 20분 기준에 27분 사용 | V=.233, T=.767; A=.90이면 .867, A=.30이면 .417 |
| 같은 27분에 프릭션 취소를 0회 또는 20회 기록 | A 결과 동일; 취소 횟수로 초과를 지우지 않음 |
| unknown이 30일 이어짐 | A 유지; 최신 상태라고 주장하지 않음 |
| partial에서 20분 기준의 확정 사용 하한 120분 | T_upper=0; A=.80이면 .600, 관측 밖 정상 사이트로 희석되지 않음 |

회복 속도 민감도: A=.30에서 준수가 4회 이어질 때 alpha=.15/.25/.35면 각각
.635/.779/.875다. 어느 속도가 적절한지는 이 표만으로 정하지 않는다.
같은 설정·같은 기록의 replay, 경계의 연속성, 단조성, 중복 불변성을 합성 검사하고,
실제 표현에서 작은 회복이 알아볼 만한지와 과한 죄책감을 만드는지를 별도로 검토한다.
2026-10-09 native Node 24.14.0 계산에서는 위 표와 후보식의 범위·단조성·중복 불변성·비희석·
partial 비회복·경계 연속성에 대한 합성 검사 30,252개가 통과했다. 일일 저장·마감의 중복 방지와
표현 효과는 아직 구현·검증 대상이며 이 계산에 포함되지 않는다.
검사 그리드는 A=0부터 1까지 .05 간격, alpha=.15/.25/.35/1, g=.5/1/5/20/60/240분,
사용량/목표 비율=0/.25/.5/.95/1/(1+1e-8)/1.15/1.5/2/4다. 목표 및 포화 경계의 양쪽
1e-7분 차이도 비교했다. 상태 범위와 단조성은 위 convex combination의 대수적 성질과 함께 판단한다.

## 6. 회복의 시각적 표현

수치에 앞서 표현의 인과관계를 고정한다.

| 원천 | 표현 원칙 |
| --- | --- |
| 누적 S | 줄기·가지의 성숙과 개체 정체성. 일일 위반으로 축소하거나 나무를 초기화하지 않음 |
| 최근 A | 작은 가지의 자세, 잎과 목질의 생기, 꽃의 존재·밀도·화사함. 한 원천에서 일관되게 파생 |
| A가 실제 상승한 닫힌 결과 | 봉오리·자세·색의 작은 회복을 먼저 보이고 반복된 개선에서 전체 생기가 따라옴. T 개선만으로 A 하락 중의 나무를 회복시켰다고 표현하지 않음 |
| 확정된 R | 필요한 경우 희소하고 짧은 행동 피드백. 추가 꽃 재화나 회복 가속으로 바꾸지 않음 |
| Q와 자료 없음 | 기본 홈에서도 마지막 관측 기반임을 구분하는 조용한 표시를 제공하고 상세에 시점을 표시. 시듦이나 숨은 회복의 원인으로 쓰지 않음 |

같은 A에서 나무 크기·종자·카메라가 달라도 상태를 읽을 수 있어야 한다. 낮은 A도 아름답고
살아 있는 나무로 유지하며, 죽음·돌이킬 수 없는 손실·타이머로 복귀를 압박하지 않는다.
배지는 필요한 상세에만 두고 기본 홈은 조용하게 유지한다.
단, 오래된 높은 A를 최신 준수처럼 읽게 해서는 안 된다. 관측이 끊겼을 때에는 새 회복 연출을
만들지 않고 마지막 확인 상태라는 최소 구분을 홈에 남긴다. 수집 재개를 압박하는 문구는 두지 않는다.

현재 Home은 Plume이며 기존 모델의 모든 표현이 연결돼 있지 않다.
[제품 엔진 owner](../../architecture/themes/zen/zen-g15-product-engine.md)의 현재 경계를 따라,
가지 처짐·실제 꽃 밀도·꽃 색·회복 표현을 각각 낮음/중간/높음의 동일 개체로 확인해야 한다.
debug 슬라이더는 표현 검토용이며 저장된 행동 결과를 바꾸지 않는다. 형태에 습관을 영구 각인하는
설계는 이번 최소 모델에 넣지 않는다.

현재 five-qualified-use-day 구조 공개는 유지 대상으로 분리한다. 다섯 번째 비연속 자격 활동일에
첫 완성 형태를 공개한다. 최근 활성화·관측 신뢰도는 별도 축이며, 기존 7일 calibration을
구조 공개 기간으로 읽지 않는다.
자연 날씨는 습관과 독립적인 시간·계절 입력으로 비·낙화·비 뒤 낙화를 표현한다.
30일 성장이나 성숙 이후 계절 주기는 아직 구현하지 않았다. 보호 사이트 방문을 공개 자격으로
삼는 정책에는 일부러 방문할 유인이 남을 수 있으므로 후속 성장 설계에서 검토한다. 이를 활성화의
자격 조건이나 과학적인 5일 습관 형성으로 확대하지 않는다.

## 7. 시간 경계와 저장 소유권

다음은 구현 시 필요한 계약이며, 아직 존재하지 않는 능력은 명시적으로 추가해야 한다.
UI hook이나 localStorage에 새 계산 원장을 두지 않는다.

```text
확정 stats facts + 실제 적용된 기준 + 관측 범위
    → 순수 활동일 판정
    → background의 닫힌 결과와 revision
    → 순서가 보장된 A replay / checkpoint
    → theme-neutral DTO
    → Zen의 S / A / Q / B 표현
```

| 책임 | 현재 재사용할 owner | 필요한 확장 |
| --- | --- | --- |
| 사용 facts와 확정 구간 | stats collection / hourly aggregate / typed stats stores | 누락·절단 상태를 보존하며 기존 facts 재사용. 별도 usage mirror 금지 |
| 관측 충분성 | settingsCollectionAdmission과 capture metadata | 현재 worker-local proof를 재사용하되 활동일 전체의 연속 관측을 증명하는 영속 계약은 추가 필요 |
| 프릭션 노출·선택 | InterventionEffectStore / effect recorder | 명시적 leave와 확정 종료·후속 관측의 관계 및 조회 계약. 기존 reentry 의미를 바꾸어 읽지 않음 |
| 활동일 경계 | CycleStateManager와 stats temporal projection | UTC 시작·종료, timezone, reset policy를 일일 결과에 귀속. 하루를 무조건 24시간으로 만들지 않음 |
| 평가 기준 | settings command/transport와 SettingsService | 수락·effective period·재현 가능한 정책 revision/snapshot. interaction ID를 정책 hash로 쓰지 않음 |
| 순수 판정 | stats analysis의 좁은 seam | complete/partial/unknown과 규칙별 근거를 가진 결과 DTO. UI의 scored gate와 분리 |
| 닫힌 결과·A replay | stats background finalization와 platform typed storage | 활동일별 파생 결과, correction revision, idempotency, checkpoint 계약 필요. 현재 Home ledger가 대신하지 않음 |
| 시각화 | Zen life/experience/render owners | 공통 A/Q를 소비하며 renderer 내부에서 다른 건강 점수 계산 금지 |

일일 결과에는 최소 활동일의 정확한 시작·종료, 적용 policy/model version, facts revision과 마감
watermark, collection scope/완전성, 규칙별 g/u/초과 근거, T 또는 품질 상한, 판정 상태,
correction revision이 필요하다. A checkpoint에는 반영한 마지막 결과와 그 revision을 둔다.
이는 최소 의미 계약이며 물리 스키마와 테이블 이름은 storage owner 검토에서 정한다.

현재 `STATS_DAILY`는 정책 비의존 facts의 조회 인덱스다. 이 제안의 정책 의존 결과를 해당 row에
즉흥적으로 추가하지 않는다. 노출 원본과 집계의 보존기간도 다르므로 모든 과거를 언제든 다시
계산할 수 있다고 약속하지 않는다. 결과·정책·checkpoint의 보존 및 삭제 범위는 함께 결정한다.

- 목표 변경은 보호 설정의 현재 적용과 평가의 소급 재해석을 구분한다. 권장안은 진행 중인 활동일의
  평가 기준을 고정하고 새 평가 목표는 다음 경계부터 적용하는 것이다. 변경 자체에는 보상을 주지 않는다.
- 기준이 느슨해져 이후 준수가 늘 수는 있다. A는 자기 기준 준수이므로 이것을 보편적 습관 개선으로
  해석하지 않으며 기준 변경 전후의 비교에는 변경 표시를 둔다. 이전 위반을 지우지 않는다.
- cycle/reset 변경은 기존 경계 owner를 따른다. timezone 및 실제 기간 이력을 재현하는 durable 계약은
  새 period-history 확장에 포함한다. 완료된 시간 구간을 다시 열거나 중복하지 않는다.
- 진행 중인 평가의 UTC 종료 경계는 고정한다. reset/timezone 변경으로 생긴 전환용 짧은 구간은
  별도의 상향 적분 자격을 만들지 않고 해당 평가기간에 묶어 한 번 계산한다. 날짜 이름이 여러 개라고
  alpha를 여러 번 적용하지 않는다. 경계 변경의 합법적인 여행·생활 리듬 조정과 farming을 함께 검토한다.
- daily ledger는 UI와 무관하게 background가 durable facts로 마감한다. service worker가 자정에 깨어
  있을 것을 가정하지 않고 다음 활성화에서 완료 가능한 모든 보존 구간을 순서대로 처리한다.
- catch-up의 계산량은 chunk로 제한하되, 실제 일수의 의미를 7일 등으로 잘라 바꾸지 않는다.
  원본이 이미 보존기간 밖이면 gap을 기록하고 unknown으로 남기며 사실을 재구성하지 않는다.
- late facts나 정정은 같은 날을 추가 적분하지 않고 해당 revision 이후를 replay한다. 재시작·조회·Home
  재방문이 결과를 중복 반영해서는 안 된다. 쓰기 실패 시 cursor를 전진시키지 않는다.
- 정정일보다 앞선 checkpoint와 그 뒤의 결과·정책을 보존해야 해당 구간 replay가 가능하다. 원본이나
  중간 결과가 이미 삭제돼 불가능하면 replay-unavailable/error를 노출하며 현재 정책이나 기본값으로 메우지 않는다.
- 일반 stats 화면의 `policyBasis: current`는 유지한다. 마감된 습관 결과의 당시 기준 조회는 별도의
  명명된 seam이며 현재 정책 query를 조용히 변경하지 않는다.

[저장 경계](../../system-architecture/02-runtime-storage-boundaries.md)와
[저장 버전 정책](../../architecture/storage/storage-versioning-and-migration-policy.md)을 따른다.
새 persisted data class는 typed store/registry/reset/export/retention/security 계약을 함께 정의한다.
의미나 shape가 바뀌면 해당 owner의 storage version을 함께 올린다.
기존 H를 새 A로 읽기 전환하거나 자동 보정하는 legacy fallback은 두지 않는다. 공개 후 전환이라면
명시적인 버전 전환 owner와 증거가 필요하며, pre-release의 비호환 자료를 자동 삭제·변환하지 않는다.

## 8. 채택 순서와 완료 기준

1. **증거 의미 확정:** 시간 예산의 종류·적용 시점, 관측 상태, leave/종료/reentry 의미를 contract로 정의.
   유효한 하한이 남으면 partial, 판단 근거가 없으면 unknown으로 남긴다. 잘못 해석한 집계의 사용을 끊는다.
2. **일일 원장 확정:** 활동일 owner와 당시 기준, idempotent 마감·정정·replay·typed storage를 갖춘다.
   Home 방문 유무가 같은 A를 만드는지 확인한다.
3. **모형 검증:** 합성 시나리오로 후보식과 대안을 비교한다. alpha/tau, 첫 판정, 다중 기준 max의 한계,
   complete 비사용, 과사용 감소 중의 회복을 확인하고 값과 설명을 함께 결정한다.
4. **표현 검증:** 동일한 Plume 개체의 단계별 자세·색·꽃 밀도를 비교한다. 초기 회복이 보이고 누적 성장은
   유지되며, 자료 없음이 실패처럼 읽히지 않는지 확인한다.
5. **사용성 평가:** 자발적인 로컬 검토에서 의미 이해·통제감·후회·부담·해제 이유를 분리해서 본다.
   새 자기보고 수집은 별도 설계 대상이며, 원격 계측이나 자동 최적화를 도입하지 않는다.

### 반드시 통과할 시나리오

| 시나리오 | 완료 기준 |
| --- | --- |
| 기준을 정확히 지킴 / 조금 넘김 / 경계 전후 1초 | 판정 이유가 명확하고 표시 수치 반올림 전 모델 값이 연속 |
| 정상 사이트·중복 규칙·프릭션 20개 추가 | 기존 위반을 희석하거나 A의 갱신 횟수를 늘리지 않음 |
| 프릭션 없이 안정적인 준수 | 높은 A 유지 가능. ritual을 만들어 낼 필요 없음 |
| 충분히 관측된 비사용 / row 부재 / 수집 중단 | 준수와 unknown을 구분. 수집 해제로 회복을 얻지 않음 |
| 높은 A에서 수집 중단 | A를 벌점으로 내리지 않되 마지막 확인 기반임을 기본 홈에서도 구분 |
| 부분 기록의 확실한 초과 + 업무 사이트 수집 추가 | 확인된 위반이 사라지지 않고 더 넓은 동의를 요구하지 않음 |
| 첫 partial의 확정 초과 뒤 첫 complete 준수 | 초기 seed에서 순서대로 반영하며 과거 위반을 지우는 재초기화 없음 |
| 지원하지 않는 기준 하나 + 유효 기준의 초과 | 해당 오류와 aggregate partial을 노출하며 확정 위반 유지 |
| 낮은 A에서 큰 초과가 작은 초과로 개선 | 일부 회복 가능하되 남아 있는 위반을 숨기지 않음 |
| 목표 완화 / 자정·04시·timezone·DST 변경 | 새 경계의 정책을 설명 가능하며 과거 삭제·중복 마감 없음 |
| reset/timezone 변경으로 짧은 구간 여러 개 생성 | 같은 평가기간에 합쳐 계산하고 추가 회복 기회 없음 |
| Home 매일 방문 / 한 달 뒤 방문 / worker 재시작 | 같은 원본·정책·revision이면 같은 결과 |
| late facts / 마감 쓰기 실패 / 원본 보존기간 만료 | idempotent correction 또는 명시적 gap. 기본값 복구 없음 |
| A 낮음과 회복, 자료 없음 | 성장·개체 정체성 보존. 가지·꽃·색이 한 상태를 일관되게 전달 |

수학적 검사 통과는 효과 입증이 아니다. 사용성 검토에서도 화면을 오래 보게 만들거나 도구 재방문을
늘리는 것을 성공으로 삼지 않는다. 같은 약속을 더 쉽게 지키고, 의미를 이해하며, 부담이 과하지 않은지를
본다. [현재 연구 경계](../backlog/friction-effect-research-backlog.md)에 따라 숨은 A/B, 보호 강도 무작위화,
자동 개인화 최적화는 이 제안의 채택 범위에 포함하지 않는다.

## 9. 남은 제품 결정

권장 방향은 앞 절의 최소 모델이다. 구현 전에 닫을 구체적인 결정은 다음과 같다.

- alpha/tau와 표현 단계: 임의의 과학적 일수 대신 합성 민감도와 사용자 이해를 근거로 선택한다.
- A_seed와 자료가 적은 날의 표현: 첫날의 과도한 낙인이나 근거 없는 활력을 피한다.
- 다중 약한 위반의 집계: v1의 max가 놓치는 누적을 추가할 필요가 있는지 판단한다.
- 0분 회피·시간대·계획한 종료: 시간 예산과 다른 규칙의 수락·관측·판정 계약을 별도로 세운다.
- 성장 자격의 유인: 현재 5일 공개 기간은 채택된 기준으로 두고, 보호 사이트 방문의 자격 조건은 별도 성장 설계에서 검토한다. 30일 성숙 이후 주기는 미구현 제안이다.

각 결정은 관련 Active 문서·구현·지속적인 계약 검사를 함께 갱신할 때 현재 정책이 된다.
