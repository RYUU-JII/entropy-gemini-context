## 1. 출시 가치와 제외 범위

사용자는 목록에서 시간을 많이 쓰는 사이트를 찾고, Intel에서 그 사용의
형태와 근거 하나를 이해한 뒤 떠날 수 있어야 한다. 매일 방문, 전체 기록
열람, 분류 완료나 설정 변경은 성공 조건이 아니다.

- Intel에는 추천 액션, 도메인별 기능 조정, 개별 아티팩트 편집을 넣지 않는다.
- 사이트 등록, 보호/기록/제외와 개별 시간 한도는 기존 관리 영역에 남긴다.
  Intel 하단의 보호/해제/제외 버튼을 정리할 때 필요한 관리 동선을 먼저
  연결하고, 기존 명시적 확인·해제 유예·저장 실패 처리 계약을 보존한다.
- 새로운 위험 점수, 피드 소비량 점수, 알림 배지/미확인 건수, 추천 엔진,
  URL 경로 분석, 콘텐츠 식별과 추가 수집은 이번 출시 패치에 포함하지 않는다.
- 공통 구조를 사용하며 시각 조정과 시각 QA는 Zen에 집중한다.

## 2. 화면 구조

표준 데스크톱에서 Intel은 높이가 제한된 한 작업면이다. 상단은 문장과
수치, 하단은 시간대 관측면이며, 선택·근거 전환·주기적 갱신으로 영역 크기가
바뀌지 않는다. 여러 사이트를 탐색하는 목록의 제한 렌더링/검색은 별도 책임이다.

항상 남는 것은 대상 식별, 읽는 범위와 최소 기초정보다. 기존 사이트 정책
헤더에 이미 있는 식별 정보를 큰 헤더로 다시 만들지 않는다. 기본 요약은
대표 문장 하나와 같은 주장의 근거 최대 두 개를 제공한다. 데이터가 부족하면
기초 관측만으로 완성된 화면을 만들며 패턴을 억지로 채우지 않는다.

`요약 / 근거`는 같은 자리를 교체하는 직접 선택 조작이다. 큰 수치·라벨의
작은 `근거` 조작에서도 연결한다. 처음부터 조작 가능성을 표시하고 키보드로
접근할 수 있어야 한다. 자동 순환, 강제 순서, 완료 표시, 무한 캐러셀은 없다.
통찰 설명은 근거 화면의 짧은 본문에 포함하고 세 번째 추천 페이지를 만들지 않는다.

근거 화면의 정보 예산은 이유 최대 두 가지, 해석 한두 문장, 관측 범위다.
현재 펼침의 긴 근거 목록·날짜별/시간별 기록표를 그대로 옮기지 않는다.
전체 terminal 근거 데이터는 정본에 남기되 출시 화면의 기본 순회 항목으로
만들지 않는다. 핵심 원 수치·기간·비교 의미는 그래프 없이도 읽을 수 있게 한다.
시간대별 값 탐색은 차트의 클릭/키보드 선택과 고정된 한 줄 readout으로
제공한다. 24행 표나 별도 팝업으로 화면을 확장하지 않는다.
패턴별 보충 설명은 locale JSON을 정본으로 하며, 주장/한계 연결은 기존
terminal evidence descriptor 경계를 사용한다.

표준 viewport에서는 패널 및 내부 본문의 스크롤, 잘림과 자동 글자 축소가
없어야 한다. 먼저 정보량과 고정 슬롯을 조정한다. 큰 글씨/극단적인 창 크기는
별도 접근성 재배치로 다루고, 모든 화면 크기에서 스크롤을 금지한다는 약속으로
정보 접근성을 희생하지 않는다. 우선 검증은 기존 desktop-wide/compact와
portrait-narrow를 사용하며, 낮은 높이는 QA 정본의 desktop-low(1440×720)로 검증한다.

## 3. 시간대 관측면과 근거 연결

고정 00–24시 축, 옅은 누적 사용 면, 필요할 때만 드러나는 근거 강조를
사용한다. 이 면은 사용이 하루의 어느 부분을 차지했는지 보여준다. 새로운
심리 압력/위험도 점수로 해석하지 않는다. 시간과 횟수의 축은 분리한다.

현재 코드에서 확인한 범위:

| 자료 | 현재 정본 | 허용된 표현 / 제한 |
| --- | --- | --- |
| 최근 시간대별 사용 | detail의 `habitHourly`와 `weeklySeries` | 현재 포함 달력일 누적 분포. 평균이나 일관된 반복으로 재명명하지 않음 |
| 오늘의 사용·접속 | `todayHourly`, `todayHourlyVisits` | 같은 오늘 범위의 별도 시간/횟수 띠. 각 시간 안의 정확한 사건 순서는 미공개 |
| 반복 시간대 | `recurringTimeEvidence` | 완료 30일 기준의 승인된 창만 사용. 7일 분포의 판정처럼 겹치지 않음 |
| 긴 세션·전환·피드·백그라운드 | terminal evidence의 값·기간·provenance | 공개된 집계로 설명. 임의의 타임라인 위치, 사건 순서나 배타적 점유율을 만들지 않음 |
| 개인 기준 비교 | terminal에서 승인된 현재/기준 쌍 | 동일 측정값의 0 시작 비교. 서로 다른 단위·모집단을 합치지 않음 |

대표 문장의 첫 근거가 오늘 사용량·접속 분포와 직접 연결되면 요약부터 같은
자료를 보여준다. 요약/근거 전환이나 두 번째 수치의 설명을 열어도 지도 기간과
단위는 유지한다. 시간 좌표를 연결할 수 없는 근거에는 기존 최근 7일 분포를
맥락으로 표시한다. 자료가 맞지 않으면 강조를 만들지 않으며, 오늘의 판정을
최근 7일의 판정으로 승격하지 않는다.
반복 시간대처럼 별도 기간을 쓰는 근거는 그 기간의 지도/범위 계약이 준비된
후에만 연결한다. UI가 기간이나 평균을 재구성하지 않는다.

출시의 직접 시간대 연결은 사용량과 접속 분포부터 완성한다. 필요한 최근
접속 분포는 기존 day projections에서 선택 상세 read-model owner가 집계하고,
새 수집 없이 공개 가용성을 명시한다. 긴 세션이나 피드 집계를 시간대에
배치할 근거가 없으면 큰 수치와 관계 설명을 사용하고 지도는 맥락으로 유지한다.

## 4. 유한한 시각 표현과 프라이버시

범용 다이어그램 엔진 대신 근거 종류별 작은 표현 집합을 둔다.

1. 시간대 분포와 승인된 창의 강조.
2. 동일 시간축의 접속 횟수 띠(시간 면과 단위/척도 구분).
3. 허용된 현재/개인 기준 쌍의 비교.
4. 시각 좌표 없는 집계의 수치와 짧은 관계 설명.

도메인별 분기 대신 evidence family와 공개 provenance에 연결한다. 어댑터별
신호 검증은 수집/분석 소유자 책임이며 UI에 서비스별 탐지 규칙을 넣지 않는다.

기존 피드 전진·빠른 스크롤·short-media 신호는 기록된 동작의 흔적이다.
게시물 소비 수, 콘텐츠 종류, 실제 시청 내용이나 이용 목적의 확정값이 아니다.
긴 세션을 롱폼 시청으로, navigation.link 집계를 내부 콘텐츠 탐색으로 치환하지
않는다. 그러한 소비형태 추정은 provenance/반례 검증을 선행하는 별도 연구다.
기록 제외와 정밀 기록 비허용은 현재 정본 admission을 그대로 따른다.

## 5. 시스템 소유권

`수집 facts → canonical stats query/detail → terminal interpretation/readout
→ 공통 표시 모델 → 공통 읽기 구성 → Zen 재질`의 단방향 흐름을 유지한다.

- 패턴 선택·가용성·근거 ID·기간·모집단은 도메인/조회 정본에서 공개한다.
- 시간대 근거 참조에는 기간/basis, 단위, 버킷 의미, 가용성, 출처와 연결 가능한
  evidence ID를 명시한다. 미관측과 관측된 0을 구분하며, 관측 marker를
  한 시간/하루 전체의 연속 관측으로 승격하지 않는다.
- UI는 허용된 연결과 좌표를 표시한다. 임계값, 대표 패턴, 평균/집중 점수,
  근거 우선순위를 새로 계산하지 않는다.
- 기존 snapshot/detail 조회, bounded cache, revision admission과 permission
  withdrawal을 유지한다. 통찰용 두 번째 저장소/폴링/미러를 만들지 않는다.
- 분석 모델 v5의 분류·점수를 이번 UI를 위해 조정하지 않는다. 출력 계약 변경이
  필요하면 그 소유자에서 버전·소비자·테스트·문서를 함께 갱신한다.
- 현재 출력 계약 v3는 관찰을 설명하는 `explanationKey`를 terminal descriptor에서
  공개한다. 근거 본문은 설명을 먼저, 필요한 기준·한계 설명을 그다음에 읽게 한다.
- 출력/라벨/설명/선택 상태가 facts나 baseline 입력으로 역류하는 경로를 허용하지 않는다.
- 조회 갱신은 페이지 전환/진입 효과를 재생하지 않는다. 현재 근거 화면과 포커스를
  유지하며 사이트 전환·권한 철회의 기존 격리를 지킨다.

## 6. 스케줄과 전체 흐름: 후속 청사진

이번에는 문서만 마련한다. 의미가 정해지지 않은 pin/interval 런타임 API,
빈 서비스, 비활성 토글이나 예비 저장 키를 만들지 않는다.

향후 목록의 별도 `전체 흐름` 진입점에서 여러 사이트와 사용자 지정 시간
구간을 함께 읽는 방향을 검토한다. 개인 사이트 Intel에 전역 계획 분석을 넣지 않는다.

- Schedule owner: 사용자 구간/핀의 의미, ID, 실제 시간 범위, 시간대와 revision,
  적용 시점/이력. 완화 세션을 업무 구간으로 자동 간주하지 않는다.
- Stats read-model owner: 승인된 기록 범위와 사용자 구간의 시간 겹침/관측
  모집단을 투영. UI에서 캘린더나 원시 기록을 직접 결합하지 않는다.
- Insight owner: 근거가 있는 겹침과 반복만 설명. 현재 바뀐 스케줄을 과거의
  실제 의도로 소급하지 않으며, 현재 계획에 비춰본 가상 비교라면 그렇게 표시한다.
- Presentation owner: 같은 시간대 작업면에 구간을 배치. pin 알림과 아티팩트
  호출/링크 메시지는 스케줄 액션 소유자가 실행하고 Intel은 실행자가 되지 않는다.

첫 가치는 `내가 업무로 지정한 구간과 보호 사이트 사용의 겹침`이다.
기록 범위가 보호 사이트만이면 전체 브라우징 대비 비중을 주장하지 않는다.
관측이 없는 시간이나 보호 사이트를 덜 쓴 시간을 집중/생산성으로 판정하지 않는다.
`집중이 잘 되는 시간`은 그 주장을 뒷받침할 별도 관측/검증 없이는 제공하지 않는다.

## 7. 패치 순서와 종료 조건

| 단계 | 작업 | 종료 조건 |
| --- | --- | --- |
| 1. 출시 계약/정보량 | 기본 관리 동선과 Intel 분리, 요약/근거 정보 예산, 기간·시각 연결 표, 지원 viewport 확정 | 모든 대표 사례가 고정 면적에서 할 역할이 명확하고 필수 관리 조작이 사라지지 않음 |
| 2. 근거 연결 데이터 | 기존 선택 상세/terminal 경계에 사용·접속의 기간/가용성/참조 연결, 필요한 typed projection만 추가 | 새 수집 없이 같은 기간만 연결되고 0/미관측·집계/사건 위치가 구분됨 |
| 3. 공통 화면/Zen | 상단 읽기와 하단 지도, 동일 자리 요약/근거 전환, Intel 액션/긴 펼침/중첩 스크롤 제거 | 기본·근거 모두 표준 viewport 안에 완결, 키보드로 설명과 핵심 값 접근 가능 |
| 4. 작업면 연결 | 그래프 배경의 오른쪽 끝 연결, 선택 행의 면과 Intel 연결, 작은 우측 이동/선택 구간 강조 | 스크롤바 자리의 흰 띠와 선택 폭 변화가 없고 긴 도메인/행 높이/탐색 안정성 유지 |
| 5. 검증/인계 | 집중 계약 테스트, 정본 guard, Zen named capture/recording-refresh, i18n 생성, 제품 문서·개발 dist 갱신 | 실제 캡처/동작 결과와 미해결 범위를 정직하게 기록 |

기존 고정 stage를 축소해 내용을 끼워 넣는 작업부터 시작하지 않는다. 먼저
원시 근거→표시 관계를 확정하고, 사용/접속의 핵심 두 사례를 완성한 후 다른
기존 통찰을 같은 표현 규칙에 연결한다. 사이트별 임의 디자인을 늘리지 않는다.

주요 검증: 동일 60분의 긴/분절 사용, 시간대에 없는 세션 위치를 만들지 않음,
부분 기록과 0, 오늘/최근/30일 혼합, 기준 0, 기록 권한 철회, 같은 사이트 갱신,
