# 식어가는 사이클 (Cooling Cycle) 제품 노트

- Status: Active
- Owner: dashboard product / protection runtime
- Last validated against code: 2026-10-14
- Path policy: planning-allowed
- Canonical for: P1의 냉각 곡선·설정·첫 화면 경험과 목표 도달 표현; P2–P4와 남은 체험 검증은 별도 제안으로 구분한다.

런타임 계약, 데이터 형태와 owner는
[Cooling Curve Runtime](../../architecture/runtime/cooling-curve-runtime.md)이 맡는다.
이 노트는 사용자가 겪는 경험과 화면만 다룬다.

이 문서의 정기 점검은 **Tools → Barrier → 소비 간격**이다. Zen의 Enso
작품(궁극의 원)은 Veil의 시각 표현이며 이 설정과 별개다. 코드에 남은
`ensoGate`·`Enso*`는 클릭/피드 경계 실행을 가리키는 내부 이름이고, 제품에서
정기 점검을 Enso 아티팩트라고 부르지 않는다.

2026-10-13 합의 방향은 P1에서 Site Furin을 유지하고, P2에서 사이트 목표의 끝맺음을
Horizon 또는 Furin 하나로 표현하는 것이다. 지원되는 피드에서는 Site·Global Furin
앞에 Horizon이 반드시 선행한다. Barrier 정기 점검을 꺼도 이 준비 단계는 작동한다.
Barrier 정기 점검은 별도 선택이며, Furin보다 가벼운 중간 점검으로 설계한다.
P1-A 공통 경계, P1-B 목표 취소·표시 기록, P1-C 곡선·설정·첫 화면 적용을 구현했다.
이 노트는 구현된 경험의 정본이며, 출시 전 지원 화면·체험 검증과 가벼운 정기 선택은
남은 과제로 구분한다. P2–P4는 제안이다. 데이터·실행 계약은 연결된 런타임 문서가 맡는다.

## 구현 범위 · 2026-10-13

- **P1-A 공통 경계:** 지원 피드에서 Site·Global Furin 앞에 Horizon을 놓고, 실제로
  만난 뒤 새로운 계속 행동으로 같은 경험의 Furin에 이어진다. Barrier 정기 점검 OFF여도
  준비한다. 경계를 본 사실과 실제 Furin을 본 사실은 따로 다룬다.
- **안전한 비피드 진입:** 선언된 새 콘텐츠 선택 행동과 정확한 준비 허가로 제한한다.
  미확인 피드·주 영상 종료를 증명하지 못한 혼합/단독 미디어는 대기한다. 일반적인
  일시정지나 종료 이벤트만으로 Furin을 띄우지 않는다.
- **P1-B 목표와 기록:** 실제로 도달한 Global·Site만 고르고, 합친 안내는 그때 도달한
  현재 사이트만 포함한다. Global 뒤의 다른 사이트 안내는 짧게 남긴다. 목표가 바뀌면
  이전 준비를 정확히 정리할 때까지 취소 상태를 유지한다. 실제 표시 기록은 선택 완료와
  분리하며, 기존 Filter 상태에서 대기·지원 확인 필요·오류·전달 완료를 읽는다.
  새로운 정기 점검을 허가하기 전에도 도달한 미전달 목표를 다시 확인한다. 이미 진행 중인
  일반 경험은 목표가 뒤늦게 도달했다는 이유로 빼앗지 않는다.
- **P1-C 곡선과 설정:** 설정 → 보호 방식의 부드럽게 / 표준 / 가파르게 한 설정을 쓰고,
  Tools의 Lens·Veil·Brake·Barrier에서 곡선/고정을 고른다. 기본은 표준, Brake만 고정이다.
  켠 효과만 단계적으로 바뀌며 목표 없음·기록 없음에서는 고정 세기와 이유를 표시한다.
  새 페이지도 배경에서 계산한 같은 단계로 시작한다. 고급 값은 저장 계약에 포함되지만
  편집 화면은 P3다. Global 최대 보호·일시 해제는 별도로 표시한다.
- **개발 프로필 경계:** 예전 `globalFrictionLevel` 설정과 V1 일일 기록은 자동 변환하지 않는다. 호환되지 않는
  개발 프로필은 안내된 전체 초기화를 직접 선택해야 하며, 이 작업이 초기화를 실행하지 않는다.
- **아직 남은 범위:** 가벼운 정기 점검 UI, 의미를 확인하는 미디어 종료 지원과 화면별
  검증과 가까운 두 목표의 체험 확인,
  P2의 Horizon 단독 끝맺음. 구현 코드만으로 전체 P1 출시 검증을 마쳤다고 주장하지 않는다.

2026-10-14 실제 사이트 QA에서 목표 시간 기준의 불일치를 발견했다. 헤드리스에서도
TikTok 활성 시간 약 178초가 실제 기록·저장됐지만, 사이트를 그 시간 중간에 등록하면
Sites·Global 집계가 시간 시작 시점의 규칙으로 다시 분류해 0으로 남았다. Site 곡선·Furin은
사이트의 전체 활성 시간을 읽으므로 세 경로가 다른 시점에 목표에 도달할 수 있다.
이는 아래의 같은 시간 기준 약속을 충족하지 못하는 출시 전 수정 항목이다.
이 실패를 우회해 Horizon → Furin, 가까운 목표 중복 방지, 목표 변경 취소를 통과했다고
보고하지 않는다. 구체적인 실행·집계 경로와 남은 검증은 연결된 런타임 문서에 기록했다.

## 왜

목표 사용량은 **보호가 유효한 동안 기록한 활성 시간**으로 통일한다. Sites의 남은
시간·냉각 곡선·Site Furin은 같은 차감량을 사용하고, Global은 같은 기준의 사이트별
차감량을 합산한다. 전체 이용 통계는 별도 관측량으로 유지한다. 14:37에 등록하면
그때부터 같은 시간대 안에서 차감하며, 등록 전 이용은 소급 차감하지 않는다.
목표 수정은 사용량을 초기화하지 않고, 보호 해제·재등록도 기존 차감량과 표시 기록을
지우지 않는다. 기록 제외·동의 철회에 따른 현재 열람 제한은 유지한다.
이전 시간별 합계에서 정확한 차감량을 추정하지 않으며, 이전 개발 데이터 형식은
자동 변환·삭제하지 않는다. 새 형식으로의 개발 프로필 초기화는 명시적 작업이다.

공개 피드 랜딩은 "끝없는 피드에, 끝을"을 보여 준다. 피드는 색 → 신호 → 흐림 → 글자
순서로 식고, 마지막에는 아무것도 묻지 않는 Horizon에서 끝난다. 지금 확장의 고정 세기와
단계적인 예산 강화에는 이런 경사가 없다. 식어가는 사이클은 사용자가 정한 하루 목표를
그 경사와 연결한다. 끝맺음도 보고 있던 콘텐츠를 마칠 수 있는 경계에서 시작해야 한다.

## 경험

1. **입력은 하나.** Sites에서 이미 정하는 사이트별 하루 시간 목표를 그대로 쓴다.
   들어갈 때마다 목표를 묻는 화면은 v1에 없다.
2. **곡선도 하나.** 목표 시간을 많이 쓸수록 사이트가 식는다. 기본(표준)의 기준 구간은
   색 22% → 반응 신호 42% → 흐림 58% → 글자 리듬 76%다. 실제 변화는 단계화와 갱신
   주기에 따라 늦어질 수 있다. 각 효과는 사용자가 정해 둔 기준 세기까지 올라가고,
   목표 직전에는 지금의 한 단계 "강화"까지 올라간다. 끈 효과의 구간은 표시에서 건너뛴다.
3. **사이트 목표의 끝맺음은 한 번.** 100%에서 곡선은 가장 식은 상태로 머물고,
   끝을 알리는 경험은 다음 안전한 콘텐츠 경계에서 시작한다.
   - 출시 전(P1): Site Furin을 유지한다. 지원 피드에서는 Horizon을 먼저 만나고,
     거기서 새로 계속하려는 행동을 했을 때 Furin이 시작한다. Global Furin도 같다.
   - 이후(P2): 지원 피드에서는 질문 없는 Budget Horizon 자체가 사이트 목표의 끝맺음이다.
     선언된 비피드 화면에서는 Furin으로 표현한다. 같은 목표에 Furin과 Budget Horizon을
     차례로 보여주지 않는다. 안전한 경계를 만들 수 없는 피드에서는 표시를 보류한다.
   - 나중: 원하는 사이트에만 켜는 하드 스톱(Torii 경계).
4. **사용자가 끈 효과는 켜지지 않는다.** 곡선은 이미 켠 효과의 시작 시점과 세기만 정한다.
5. **하루 단위.** 하루 경계(reset hour)에 처음부터 다시 시작한다. v1에서는 쉬었다 와도
   곡선이 되돌아가지 않는다.
6. **목표가 없거나 기록이 꺼진 사이트**에는 곡선 없이 고정 세기가 적용되고,
   화면에 그 이유가 표시된다.
7. **계속해도 곡선은 되돌아가지 않는다.** Site Furin에서 계속을 고르거나 목표 Horizon을
   지나가도 100% 상태를 유지한다. 직접 보호를 잠시 쉬게 하는 행동과 기존 Global 결과의
   일시 해제·강화는 따로 설명한다.

이 숫자들은 랜딩에서 가져온 출발점일 뿐, 효과가 검증된 임계값이 아니다.
Entropy는 주의·감정·의도를 측정한다고 주장하지 않는다. 시간은 포그라운드에 열려 있던
사용 시간이며, 기준은 Sites의 남은 시간 표시와 같다.
P1-C는 16단계 수식을 채택했다. 첫 색 변화는 약 26.9%, 최종 강화는 약 95.1%부터
가능하며 기존 추적 갱신 주기에 따라 반영된다. 랜딩의 기준 구간을 정확한 발동 시각으로
약속하지 않는다. 100%는 목표 도달이며 화면이 즉시 뜬다는 뜻은 아니다.

## 목표를 바꿨을 때

오래 기다리고 있는 Horizon도 현재 목표에 맞는 경험이어야 한다. 목표·기록·하루 경계가
바뀌면 준비할 때뿐 아니라 Horizon을 실제로 만날 때와 Furin을 시작할 때도 다시 확인한다.
목표 Horizon 단독 표현은 실제 만남 직전에 확인한다. 화면은 시간 비율을 따로 계산하지 않는다.

| 변경 | 아직 목표 끝맺음을 전달하지 않았다면 | 이미 전달했다면 |
| --- | --- | --- |
| 목표를 늘림 | 이전 목표로 준비한 경계를 정리. 새 목표에 아직 도달하지 않았다면 종료 안내 취소. 이미 도달했더라도 다음 새 안전 경계에서 다시 준비. | 그날 실제 전달 기록 유지. 목표 수정으로 같은 사이트의 끝맺음을 반복하지 않음. |
| 목표를 줄임 | 새 목표에 도달할 수 있지만 설정을 저장하는 순간 Furin을 띄우지 않음. 이전 준비를 정리하고 다음 새 안전 경계에서 확인. | 같은 날 전달 기회를 다시 만들지 않음. |
| 목표 삭제·해당 기록 OFF·목표 알림 OFF·보호 해제 | 영향을 받은 종료 경험만 취소. 곡선은 목표 없음/기록 없음 등 현재 상태로 갱신. 다른 근거로 유효한 Global·정기 점검까지 함께 끄지 않음. | 실제 본 기록은 유지하고, 더 이상 허용되지 않는 진행 화면은 정리. 선택 완료로 바꾸지 않음. |
| 하루 경계 도달·초기화 시각 변경 | 이전 하루 기준의 준비와 늦은 실행을 폐기하고 현재 하루의 사실을 다시 확인. 확인되지 않으면 대기/오류를 표시. | 이전 기록의 날짜를 바꾸거나 같은 날 표시 기회를 초기화하지 않음. 새 하루의 정상 기회는 기존 하루 기준을 따름. |
| 테마·언어·곡선 프리셋만 변경 | 목표 조건이 여전히 유효하면 경험 유지. 설정 번호가 달라졌다는 이유만으로 취소하지 않음. | 재표시하지 않음. |
| Site·Global을 합쳐 준비한 뒤 한쪽 조건 변경 | 합친 준비 전체를 정리하고 다음 새 경계에서 현재 도달한 목표를 다시 고름. 진행 중 문구와 전달 범위를 몰래 바꾸지 않음. | 실제 알린 목표만 원래 기록으로 유지. |

예를 들어 10분 목표로 Horizon을 준비한 뒤 목표를 30분으로 늘렸다면, 이전 경계를
넘는 행동으로 "목표 도달" Furin이 시작하면 안 된다. 반대로 이미 Furin을 보았거나 P2의
목표 Horizon을 만난 뒤 목표를 수정했다면 그 사실은 남긴다. 삭제 후 같은 날 다시 목표를
추가해도 이미 전달한 끝맺음을 반복하지 않는다.

취소는 이전 클릭·스크롤을 다시 실행하거나 다른 경험으로 즉시 바꾸는 동작이 아니다.
해당 경계를 정확히 정리하고, 새 조건에서 다음 안전한 행동을 기다린다. Furin 앞의 경계만
본 경우에는 그 노출 사실을 남기되 Furin 표시나 목표 전달 완료로 기록하지 않는다.
이미 전달한 뒤 조건이 바뀌면 필요에 따라 진행 화면을 닫고 실제 종료 이유를 남긴다.

## Horizon은 공통 경계, Barrier 정기 점검은 별도 선택

Horizon은 소비 흐름 안의 읽을 수 있는 경계다. Barrier 정기 점검은 그 경계를 중간 점검에 쓰는
선택이다. 둘을 하나의 ON/OFF로 묶지 않는다.

| 사용 목적 | 사용자가 받는 의미 | 경계 이후 |
| --- | --- | --- |
| Barrier 정기 점검 | "한 호흡을 보냈어요" | 가벼운 계속/여기까지 선택 한 번 |
| Furin 앞의 Horizon | "지금 보던 것을 마치고, 여기서 멈출 수 있어요" | 새로 계속하려는 행동에 Furin 시작; 정기 점검 질문을 먼저 넣지 않음 |
| P2 Budget Horizon | "오늘 이 사이트에 정한 시간에 도달했어요" | 선언형 끝맺음; 그대로 지나가면 곡선은 유지 |

Furin만 켜져 있어도 지원 피드의 경계 준비는 작동한다. Barrier 정기 점검 OFF, Barrier 일시정지,
필터 고정 모드를 이유로 Furin 앞의 Horizon을 생략하지 않는다. 이 준비 때문에 정기
정기 점검이나 사용자가 끈 필터를 켜지도 않는다.

Horizon은 현재 항목 뒤에 놓인다. 도착한 스크롤의 관성이나 잠깐의 정지 뒤에 Furin을
자동으로 띄우지 않는다. 사용자는 읽기를 마치고 머물거나 뒤로 갈 수 있고, 새로운 앞으로
가기 행동을 해야 Furin으로 이어진다. Horizon → Furin은 질문 두 개가 아닌 하나의 경험이다.

피드 경계를 검증하지 못했으면 갑자기 Furin 화면으로 대체하지 않는다. 목표 도달 상태는
남기고 다음 안전한 기회를 기다린다. 비피드 화면도 보고 있던 콘텐츠를 마치는 행동/미디어
경계를 확인한 뒤 진입한다. 단순 시간 만료나 무입력을 콘텐츠가 끝났다는 근거로 삼지 않는다.

## 화면별 안전한 경계 판정표

아래는 P1-A에서 구현·검증할 기준이며, 현재 모든 사이트에서 작동한다는 지원 목록은 아니다.
P1-A 이전에도 수신 코드는 무입력·시간 만료를 취소했지만, 광범위한 클릭/키와 일반적인
pause/ended를 경계로 허용했다. P1-A는 이를 준비된 새 콘텐츠 선택 또는 검증된 피드
경계로 좁힌다. 의미가 확인된 미디어 종료 지원은 아직 남아 있다.
특히 Horizon을 안전하게 놓을 수 있다는 사실만으로, 함께 재생 중인
주 콘텐츠를 끊어도 되는 것은 아니다.
혼합 화면에서는 주 미디어 보호 조건이 일반 피드 판정보다 우선한다. 댓글 영역이 피드로
분류돼도 영상과 댓글 행의 조건을 건너뛰지 않는다.

| 화면 | 진입 가능한 근거 | 이것만으로는 진입하지 않음 |
| --- | --- | --- |
| 연속 피드 | 실제 전진과 현재 항목 뒤의 안전한 삽입 위치 확인 → Horizon 만남 → 새로운 앞으로 가기 행동 | 휠 입력 의도, 새 게시물 로딩, 관성, 뒤로 보기, 입력·선택 중 |
| 페이지형 쇼트폼 피드 | 실제 항목 전환과 페이지/스냅 경계·삽입 지원 확인. 현재 항목을 보존한 뒤 Horizon과 새로운 계속 행동 | 휠 연속 입력, 확인되지 않은 스냅, 자동 재생 전환만 |
| 영상과 댓글이 함께 있음 | 현재 주 영상이 자연 종료 후 여전히 종료 상태이며 후속 콘텐츠가 재생되지 않음, 또는 사용자가 다른 주 콘텐츠를 직접 선택. 지원 피드에서는 Horizon도 선행 | 댓글 스크롤, 댓글 Horizon, 일시정지·탐색·볼륨·자막, 다른 영상의 종료, 자동 다음 영상 시작 |
| 긴 글·문서 | 명시적으로 지원하는 다음 글/새 콘텐츠 선택. 문서 자체에 피드 경계를 끼워 넣지 않음 | 맨 아래 도달, 체류 시간, 읽기를 마쳤다는 추정, 무입력, 임의 링크 |
| 비피드 목록·새 콘텐츠 선택 | 실제 선택 대상이 지원되는 새 콘텐츠이고, 그 행동에 쓸 준비된 권한이 있음 | 임의 버튼/Enter/PageDown, 좋아요·펼치기·유틸리티·탈출 동작 |
| 단독 영상·음원 | 해당 주 콘텐츠가 실제로 끝났고 여전히 종료 상태이며 자동 재생 후속 콘텐츠가 없음. 또는 명시적인 새 콘텐츠 선택 | 단순 pause, 반복 재생·탐색으로 생긴 종료 신호, 다른 미디어의 ended, 이미 시작한 다음 콘텐츠 |
| 미확인·혼합 맥락을 판정 못함·현재 불안전 | 목표 도달 상태와 대기/지원 불가 이유를 남기고 다음 검증 가능한 기회를 기다림 | 일반 클릭이나 시간 만료 화면으로 대신 띄우기 |

준비된 권한이 없는 새 콘텐츠 선택은 원래대로 진행된다. 뒤늦게 이전 클릭을 재생하거나
다음 페이지 위에 Furin을 덮지 않는다. 자연스러운 미디어 종료를 쓰는 진입은 Furin을 위한
제안이며, 그 신호만으로 Barrier 정기 점검을 새로 발동시키지 않는다.

P1의 기존 Filter 런타임 상태 영역에는 "목표 도달 · 안전한 콘텐츠 경계 대기" 또는
"이 화면에서는 피드 경계를 지원하지 않음"처럼 최소 읽기 전용 상태를 제공한다.
실제 오류는 지원 불가와 구분한다. 언제 뜰지 보장하는 카운트다운은 제공하지 않는다.
Sites·팝업의 전체 진행 표시를 P2로 미뤄도, P1에서 조용히 무기한 기다리게 하지는 않는다.

## 중간 점검은 끝맺음보다 가볍게

Barrier 정기 점검은 기존 Off / 8 / 12 / 20분 선택을 유지한다. 곡선 프리셋이나 Furin을 켜는
행동이 그 선택을 바꾸지 않으며, 기존 기본값도 이 문서에서 자동 변경하지 않는다.
사이트 하루 목표와 다른 주기이므로, 켜 두었다면 목표에 도달하기 전에도 나타날 수 있다.
중간 Horizon에는 하루 목표가 끝났다는 표현을 쓰지 않는다.

제안하는 기본 인터랙션은 작은 계속/여기까지 선택 한 번이다. 제스처를 쓴다면 그 선택을
대신하는 짧고 접근 가능한 방식으로 설계한다. 선택 뒤에 제스처 게이트를 추가하거나,
Furin 전에 Barrier 정기 점검 게이트를 통과하게 하지 않는다. 시각적 무게·필요한 조작·소요 시간이
짧은 Site Furin보다도 커지지 않게 비교 검토한다. 정확한 조작과 제스처 수치는 아직 열린
디자인 결정이며, 지금의 Gesture Gate를 그대로 가져오는 것으로 확정하지 않는다.

## 겹치는 시점과 Global 이후

새 경험을 고를 때의 우선순위는 **Global 목표 → Site 목표 → Barrier 정기 점검**다.
이미 붙었거나 표시 중인 경계는 다른 일반 개입이 빼앗지 않는다. 목표 상태와 곡선은
즉시 갱신하고, 기존 경험을 정리한 뒤 다음 안전한 기회에서 미전달 목표를 다시 확인한다.
종료 뒤의 공통 간격은 유지하되, Horizon 전주곡과 Furin 사이에는 넣지 않는다.

| 상황 | 경험 |
| --- | --- |
| 사이트 목표 10분, 정기 점검 12분 | 목표 끝맺음이 먼저. 실제 Furin을 마치면 점검 주기를 새로 시작하므로 원래의 12분 점검이 뒤따라 나오지 않음 |
| 사이트 목표 30분, 정기 점검 12분 | 중간 점검이 먼저 가능. 점검을 마쳐도 사이트 사용량은 유지되며 목표 끝맺음은 별도로 한 번 |
| 목표와 정기 점검이 함께 준비됨 | 목표 끝맺음을 먼저 선택. 밀린 점검을 이어서 재생하지 않음 |
| Site와 Global이 모두 실제로 도달함 | 현재 사이트 목표도 문구에 포함한 Global 경험 하나로 합칠 수 있음 |
| Global을 본 뒤 다른 사이트가 목표에 도달함 | 그 사이트의 끝맺음은 남김. Furin이면 짧은 형식, P2의 지원 피드이면 목표 Horizon |
| 정기 Horizon을 보고 있는 동안 목표 도달 | 현재 경계를 갑자기 교체하지 않음. 곡선은 유지하고 다음 안전한 기회에서 목표 끝맺음 |

시간 예시는 다른 개입 없이 같은 시점에 시작한 경우다. 정기 시간은 보호 사이트 전반의
운영 시간이고 사이트 목표는 그 사이트의 하루 기록 시간이므로, 둘을 하나의 타이머로
합치지 않는다. 실제 표시는 안전한 행동 경계를 기다리므로 정확한 분에 보장되지 않는다.

P1-B는 Global을 봤다는 이유로 이후 모든 Site 끝맺음을 생략하던 정책을 교체한다.
목표를 정한 사이트가 각자 끝을 알려주는 일관성은 유지하고, Global 뒤의 Site Furin은
짧게 제공해 부담을 줄인다. 이미 목표에 도달한 현재 사이트를 Global과 한 번에 알린
경우에만 그 사이트의 끝맺음을 전달한 것으로 친다. 다른 사이트나 나중의 목표까지
미리 처리하지 않는다. Global 목표가 아직 남았는데 가까워졌다는 이유만으로 Global
경험으로 미리 합치던 방식도 제거한다. 이미 Global을 전달했다면
그 뒤에도 전체 사용량이 목표를 넘고 있다는 이유로 나중의 Site 끝맺음을 다시 흡수하지 않는다.

## 가까운 두 목표의 검증 시나리오

아래는 실제 화면과 체험에서 확인할 사례다. 일부 기계적 순서·기록 조건은 단위 검사로
확인하지만, 사이트별 표시와 체험 검증을 마쳤다는 뜻이 아니다. 실험용 시간·사용량은
실제 사용 관찰과 구분한다. 간격은 앞 경험 전체가 실제로 끝난 시점부터 잰다.

| 시나리오 | 지켜야 할 동작 | 체험에서 확인할 점 |
| --- | --- | --- |
| Site Furin 종료 1분 뒤 Global 도달 | Site 당시에는 Global을 미리 처리하지 않음. 공통 회복 간격 뒤 새 안전 경계에서 Global을 별도로 전달 가능 | 두 이유가 이해되는지, 끝맺음이 너무 가까워 반복처럼 느껴지는지 |
| Site 종료 15초 뒤 Global 도달 | 도달 상태는 보이되 45초 회복 중 새 의식 금지. 회복 시간이 끝났다는 이유만으로 자동 재생하지 않음 | 기다리는 이유가 분명하고 갑작스러운 연속 발동이 없는지 |
| Global 종료 1분 뒤 다른 사이트 목표 도달 | 이후 Site를 생략하지 않음. P1은 짧은 Furin, P2 지원 피드는 목표 Horizon | 사이트별 약속을 지키면서 큰 Global 경험을 반복하지 않는지 |
| Site Horizon을 기다리는 동안 Global 도달 | 현재 경계를 빼앗거나 Global로 바꾸지 않음. 정리 뒤 현재 사실을 다시 확인 | 경계가 두 개 생기거나 화면이 갑자기 교체되지 않는지 |
| 같은 새 경계에서 두 목표 모두 실제 도달·미전달 | 현재 사이트 목표를 명시한 Global 경험 하나. 실제 알린 두 범위만 기록 | 한 번의 경험으로 두 이유가 전달되고 나중에 중복되지 않는지 |
| Site 도달 시 Global까지 아직 1분 남음 | Site만 전달. 이후 Global이 실제 도달하면 별도로 검토 | 미래 목표를 앞당겨 알리지 않으면서도 연속 경험의 부담이 허용 가능한지 |
| 목표 증가/삭제·기록 OFF가 Horizon 만남 전, 만남 후 Furin 전, 최종 표시 직후에 발생 | 앞의 두 경우는 미전달 경험 취소. 마지막 경우는 실제 전달 기록 유지 | 예전 목표의 Furin이 뒤늦게 나오거나 없던 선택 기록이 생기지 않는지 |
| 여러 탭·재시작·하루 경계 변경과 두 목표가 겹침 | 정확한 사이트/하루/화면의 현재 권한만 사용. 늦은 실행은 새 날의 전달 기록을 만들지 않음 | 중복, 오래된 안내, 숨겨진 대기 없이 현재 상태를 설명하는지 |

기계 검증에서는 실제 최종 표시 횟수·목적·날짜·정리·주기 초기화가 정확한지 확인한다.
체험 검토에서는 현재 콘텐츠가 보존됐는지, 중간 점검과 목표 종료가 구분되는지, 두 번의
경험이 얼마나 부담스러운지 확인한다. 허용 간격을 미리 효과가 검증된 숫자로 주장하지 않는다.

부담이 크다면 관찰 근거를 가지고 별도의 개입 밀도 정책을 정한다. 이번 보완만으로 새
타이머를 추가하거나, 미래 Global 목표를 전달 처리하거나, 이후 Site 전체를 다시 생략하지 않는다.

## 표시와 선택 기록

- 목표 도달, 경계 준비/부착, 실제 Horizon 만남, 실제 Furin 표시, 최종 끝맺음 전달,
  사용자의 계속/떠나기 선택은 서로 다른 사실이다.
- P1에서는 실제 Furin이 보여야 사이트 끝맺음을 전달한 것으로 기록한다. Furin 앞의
  Horizon을 준비하거나 만난 것만으로 Furin 표시·선택 기록을 만들지 않는다.
- P2의 Horizon 단독 표현에서는 실제 목표 Horizon을 만난 것이 전달이다. 같은 사이트와
  하루에 다른 표현으로 다시 끝맺지 않는다. Global과 합친 경우도 실제 알린 사이트만 기록한다.
- Furin을 본 뒤 선택 없이 떠나면 표시 기회는 소비됐지만 선택 완료로 기록하지 않는다.
  선언형 목표 Horizon은 실제 만남으로 전달되며 원래 선택이 없다. 정상 종료는
  "전달됨·선택 불필요"로 구분한다. 정리/이탈 사유는 별도로 남기고, 이후 정리 실패가
  확인된 표시 기록을 지워 재표시하게 하거나 계속/떠나기 선택을 만들어내지 않는다.
  부착만 하고 보지 못했거나 준비에 실패했다면 전달 완료로 기록하지 않는다.
- 실제 정기 점검/Furin 종료는 점검 주기를 한 번만 새로 시작한다. P2의 목표 Horizon도
  실제로 만나고 끝났을 때 같은 주기 초기화를 주는 것을 제안한다. 준비만 한 경계에는
  주지 않는다. 어느 경우에도 사이트 사용량이나 곡선은 초기화하지 않는다.
- 탭 전환·재시작·표현 방식 변경·같은 날 목표 수정으로 끝맺음을 반복하지 않는다.
  하루 경계에서 새로 시작한다.

## 설정 화면 스케치

공개 편집 위치는 **설정 → 보호 방식**이다. 사이트·전체 목표 안내를 독립적으로
선택하며, 켜 둔 안내만 후보와 합친 전달에 참여한다. Tools의 Furin은 같은 선택과
작동 조건을 읽어 보여 주고 설정으로 연결한다. 일시정지는 선택을 지우지 않는 별도
동작이다. 비활성화된 개발용 Filter에는 현재 프리셋·진단·설정 링크만 남긴다.

Sites에서 대상과 시간을, Tools에서 효과·최대 세기·패밀리 모드와 Barrier 정기 점검을
정한다. 안전한 경계 대기·중복 방지·우선순위·목표 변경 취소는 앱의 공통 보장으로
설명하며 별도 스위치를 두지 않는다. 화면이 읽는 선택은 저장·재조회된 값이고,
저장 대기와 실패는 해당 제어 옆에 표시한다.

저장 형식은 `nudgeConfig.goalEnds: { site, global }` 한 곳이다. 옛 `enabled`는
자동으로 두 선택으로 바꾸지 않으며, 호환되지 않는 개발 프로필은 명시적 초기화가
필요하다. 초기화를 실행한 것은 아니다. P2의 Horizon/Furin 자동 선택은 이후 범위다.

공개 설정 UI의 관련 테스트 39개 파일·780개와 프로덕션 빌드가 통과했다.
2026-10-14에는 프리셋을 한 줄로 줄인 최종 배치도 한국어 데스크톱(1784×849)과
좁은 세로 화면(560×960)의 격리 헤드리스 QA를 통과해 이미지를 확인했다.
세로 화면에서는 안내 원칙을 펼친 하단과 Barrier 링크, 가로 넘침 없음,
펼침·스크롤 상태 복원까지 확인했다. 설정값을 바꾸는 검증은 아니다.
페이지 오류·경고·CSP 위반은 없고 정리 owner 7개가 모두 해제되었다.
실행은 `20261013155109251-dashboard-capture-708f9645`와
`20261013155926638-dashboard-capture-bf8ae8bd`다. 직전 세로 실행은 초기 프레임
대기 한도를 초과했고 병렬 검사 종료 후 같은 조건으로 재실행해 통과했다.
Zen의 동적 번역 키 오류 2건도 정리해 번역 계약·소유권 검사와 기존 컨트롤 테스트
5건이 통과했고, 캡처 관련 테스트 10건과 QA 구조 검사도 통과했다.
이 결과는 최종 설정 화면 검증이며, 실제 사이트의 목표 안내 경험을 검증한 결과는 아니다.

┌──────────────────────────────────────────┐

- 프리셋을 먼저 보여 준다. 고급 편집은 숨겨 둔다.
- 프리셋을 다시 고르면 고급 조정이 지워진다고 화면에 한 줄로 알린다.
- 패밀리별 모드는 Tools의 해당 패밀리에서만 바꾼다. 다른 곳에 두 번째 편집기를 두지 않는다.
- 중간 점검 스케치의 OFF 선택은 선택 가능한 상태 예시이며 기본값 변경을 뜻하지 않는다.
- P2의 사이트 목표 끝맺음은 기존 Site Furin의 활성 설정을 하나의 목표 끝맺음 선택으로
  설명한다. Horizon용 스위치를 하나 더 만들거나 Barrier 정기 점검 설정과 묶지 않는다.
- 최종 강화는 기준 세기보다 한 단계 올라갈 수 있음을 미리 설명한다.

## P1 구현 순서

| 단계 | 먼저 완성할 것 | 확인할 결과 |
| --- | --- | --- |
| P1-A · 공통 경계와 안전한 Furin | Furin만 켜도 준비되는 Horizon, 현재 콘텐츠를 보존하는 화면별 경계, 정기 질문 없이 이어지는 Furin, 가벼운 독립 정기 점검 | 지원 화면에서 갑자기 소비를 끊지 않고, 미확인 화면에서는 명시적으로 대기 |
| P1-B · 중재·취소·기록 | 목표 우선순위, 목표 변경과 하루 경계의 취소 규칙, Global과 Site의 정확한 전달, 표시와 선택의 분리, P1 대기 상태 표시 | 예전 목표·다른 화면·지난 날짜의 안내가 나오지 않고, 가까운 목표도 거짓 합치기나 중복 없이 처리 |
| P1-C · 곡선·설정·첫 화면 적용 | 곡선 프리셋과 패밀리 모드, 단계별 적용과 탐색 직후 첫 화면의 일치, 목표 없음/기록 OFF 설명, 실제 범위에 맞는 랜딩 문구 | 경사와 100% 유지가 위의 안전한 끝맺음 흐름에 연결됨 |

A → B → C 순서로 검토 가능한 구현 단위를 만든다. 공통 경계는 배치·진입·정리만 맡고,
목표 판단·우선순위·취소 승인은 배경 런타임, 일일 전달 cap은 기존 단일 기록 주체가 맡는다.
세 단계를 모두 검증해야 P1 출시 최소 범위를 충족한다. A나 B만 끝내고 식어가는 사이클이
완성됐다고 공개하지 않으며, P2의 Horizon 단독 목표 표현은 계속 다음 단계로 남긴다.

## 랜딩 공개 문구의 변화

| 단계 | 랜딩이 밝히는 것 |
| --- | --- |
| 지금 | 단계적 경사와 Horizon 모두 웹사이트 연출이다 |
| P1 이후 | 경사는 확장에서도 사이트별 목표로 동작한다. 지원 피드에서는 Horizon 뒤에 Furin이 이어진다. 랜딩의 선언형 Horizon 단독 끝맺음과 압축된 시간은 연출이다. |
| P2 이후 | 지원 피드에서는 사이트 목표를 Horizon 단독으로 표시한다. 다른 선언된 화면은 Furin을 사용하며, 검증되지 않은 피드에서는 안전한 표시가 보류될 수 있다. 압축된 시간은 연출이다. |

어느 단계에서도 모든 사이트에서 피드 끝을 만들거나 계속 사용을 차단한다고 약속하지 않는다.
정기 Horizon은 목표 종료와 다른 중간 점검이라고 설명한다.

## 열린 결정

런타임 문서 §10의 D1–D10과 D6 세부 항목을 따른다.

합의한 방향:

- P1은 Site Furin 유지, P2는 사이트 목표에 Horizon/Furin 단일 표현.
- 지원 피드에서 모든 Furin 앞에 Horizon 선행. Furin만 켜도 준비되며 Barrier 정기 점검 질문을
  Furin 앞에 추가하지 않음.
- Barrier 정기 점검은 Barrier의 별도 선택이고, Furin보다 가벼운 중간 점검으로 설계.

P1-C에서 채택하고 구현한 선택:

- D1: 부드럽게 / 표준 / 가파르게 곡선 프리셋 하나를 설정 → 보호 방식에 두었다.
- D2·D3: Sites와 Furin의 기록 시간을 쓰며, 목표 없음 또는 기록 OFF는 고정 세기와 이유를 보여 준다.
- D4·D5: Lens·Veil·Barrier는 기본 곡선, Brake는 기본 고정이며 빈 구간을 당겨 채우지 않는다.
- D7·D9: Global 목표는 곡선 진행률을 바꾸지 않고, 이탈이나 Site 계속하기도 당일 진행을 되돌리지 않는다.
- D8: 사용자가 선택한 16단계 수식을 유지한다. 표준의 첫 색 변화는 약 26.9%, 최종 강화는 약 95.1%다.
- D6b·D6g: Global 이후 별도 Site 목표도 짧게 전달하며, 실제 동시 도달만 합친다. 목표 변경 취소는 P1-B 소유자와 검증을 따른다.

남은 선택과 출시 검증:

- D6d: 중간 점검의 작은 선택 UI와 제스처 대안의 실제 무게·조작
- D6e: P2 목표 Horizon의 실제 종료에도 점검 주기 초기화를 줄지 (권장: 예)
- D6f: 위 화면별 판정표에 맞는 초기 지원 화면과 실제 검증 근거. 표 자체는 보완했지만
  사이트별 작동을 검증한 것으로 보지 않음
- D6h: 가까운 실제 목표의 체험 검증. 밀도 규칙을 추가할지는 결과를 보고 별도로 결정
