# Beta Launch MVP Runbook

- Status: Active
- Owner: release operations
- Last validated against code: 2026-04-06
- Path policy: current-only
- Canonical for: 2026-04-11 beta MVP gate, forced-ship scope cuts, and release-day execution rules

## Purpose

이 문서는 Entropy를 `2026-04-11`에 베타로 출시하기 위해 무엇만 고치고 무엇은 의도적으로 버릴지 고정한다. 판단 기준은 미학적 완성도가 아니라, 제품의 핵심 가치인 "즉각적 웹 소비에 마찰을 걸어 사용자가 한 번 더 의식적으로 선택하게 만드는가"다.

## Scope

- In scope:
  - 베타에서 반드시 작동해야 하는 핵심 사용자 루프 정의
  - 출시 전 필수 수정과 출시 후 업데이트의 강제 분리
  - `2026-04-06`부터 `2026-04-11`까지의 3단계 실행 절차
  - 출시 연기 조건과 출시 강행 조건
- Out of scope:
  - 미감 polish
  - 구조가 마음에 들지 않는다는 이유만의 리팩터링
  - 사용 가능 상태를 넘어서는 일반 성능 개선

## Current baseline

- 베타에서 검증할 질문은 하나다.
  - Entropy가 도파민 자극형 웹 사용 흐름에 마찰을 걸어 즉시 소비를 늦추고, 사용자의 의식적 재선택을 유도하는가
- 베타의 기준 사용자 루프는 하나로 고정한다.
  - `설정 -> 대상 사이트 진입 -> 개입 발동 -> 사용자 선택 -> 결과 저장`
- 베타 범위는 대표 방해 사이트 `4개`로 제한한다.
  - `YouTube`
  - `Instagram`
  - `X`
  - `TikTok`
- `Reddit` 는 현재 베타 범위에서 제외한다.
- `2026-04-10`부터는 신규 기능, 미감 polish, 구조 개선을 금지한다.

## Beta site support principle

사이트별 차이를 줄이기 위해, 기능 이름을 아래처럼 고정한다.

- `Shortform Block`:
  - 다른 목적으로 들어간 사이트 안에서, 별도 숏폼 서브서피스로 빠지는 것을 막는 기능
  - 예: YouTube의 `Shorts`, Instagram의 `Reels`, TikTok의 추천/팔로잉 연속 재생 흐름
- `Site-wide protection`:
  - 플랫폼 자체가 무한 스크롤, 슬롯머신형 숏폼, 빠른 재진입 구조일 때 사이트 전체 사용 흐름에 마찰을 거는 기능
  - 예: `X`, `TikTok`

판단 규칙:

- 사이트 안에 분리된 숏폼 구역이 있으면 `Shortform Block` 대상이다.
- 사이트 전체가 사실상 그런 구조여도 탐색과 의도적 단일 선택을 분리할 수 있으면
  `Shortform Block` 이 추천·연속 소비 경로를 소유하고, 별도의
  `Site-wide protection` 이 남은 소비 흐름의 마찰을 소유한다.
- 베타에서는 같은 기능을 모든 사이트에 동일하게 강제하지 않는다.

## Beta site matrix

| 사이트 | 베타 포함 | 핵심 목표 | Shortform Block | Site-wide protection | 베타 판단 |
| --- | --- | --- | --- | --- | --- |
| YouTube | 포함 | 일반 영상/검색 사용 중 `Shorts` 늪 진입 방지 | 예 | 예 | 혼합형 플랫폼 |
| Instagram | 포함 | 일반 피드/프로필 사용 중 `Reels` 늪 진입 방지 | 예 | 예 | 혼합형 플랫폼 |
| X | 포함 | 사이트 전체 사용을 덜 매끄럽게 만들고 오래 붙잡히지 않게 하기 | 아니오 | 예 | 플랫폼 전체가 무한 피드형 |
| TikTok | 포함 | 탐색/의도적 단일 재생은 유지하고 추천·팔로잉·후속 스와이프 흐름 차단 | 예 | 나중 | 탐색과 연속 소비를 분리 가능한 숏폼형 플랫폼 |
| Reddit | 제외 | - | 아니오 | 나중 | 현재 베타 사이트 범위 밖 |

사이트별 베타 계약:

- `YouTube`
  - `Shortform Block` 은 `Shorts` 진입 경로와 `shorts` 페이지를 막는다.
  - 일반 영상, 검색, 홈 사용은 유지한다.
- `Instagram`
  - `Shortform Block` 은 `Reels` 진입 경로와 `reels` 계열 페이지를 막는다.
  - 일반 피드, 프로필, 게시물 탐색은 유지한다.
- `X`
  - 베타 목적은 숏폼 차단이 아니라 사이트 전체 흐름에 마찰을 넣는 것이다.
  - 사용자가 적당히 사용하고 빠져나오도록 지원하는 것이 목표다.
- `TikTok`
  - `Shortform Block` 은 추천/팔로잉 진입점을 제거하고 `/`, `/foryou`,
    `/following` 을 `/explore` 로 보낸다.
  - 탐색, 검색, 프로필 그리드와 사용자가 고른 단일 영상은 유지하되,
    단일 영상 뒤에 예약된 후속 추천 article은 가역적으로 숨긴다.
  - Feed Flow 기반 연속 소비 개입은 별도 제품 결정으로 남기며 이 계약에
    자동 결합하지 않는다.

## [베타 출시 최소 요건(MVP) 정의]

아래 항목이 모두 충족되면 베타는 출시한다.

- [ ] 사용자가 개입 대상 웹 사용 흐름을 실제로 설정할 수 있다.
- [ ] 대표 방해 사이트 `4개`에서 개입이 안정적으로 발동한다.
- [ ] 사용자는 즉시 진입하지 못하고 최소 한 번은 의식적으로 선택해야 한다.
- [ ] 사용자의 선택 결과가 현재 세션과 재시작 이후에도 일관되게 반영된다.
- [ ] 핵심 루프 사용 중 크래시, 먹통, 치명적 지연이 없다.
- [ ] `npm run build` 가 통과한다.

아래 항목은 베타 출시 조건이 아니다.

- UI가 premium하게 느껴지는가
- 내부 파이프라인 구조가 우아한가
- 전반적인 렌더링/반응성이 완전히 최적화되었는가

## [냉정한 수정 우선순위 표]

| 항목 | 분류 | 출시 기준 | 실행 원칙 |
| --- | --- | --- | --- |
| 파이프라인 간 상태 불일치로 인해 설정, 개입, 저장 결과가 서로 다르게 동작함 | 출시 전 필수 수정 | 핵심 가치가 깨진다 | `설정 -> 개입 -> 선택 -> 저장` 중 틀린 지점만 수정한다 |
| 상태관리 구조가 비효율적이거나 중복이 많음 | 출시 후 업데이트 | 결과만 맞으면 베타 검증 가능 | 구조 개선 욕구는 백로그로 보낸다 |
| UI 미감이 마음에 들지 않음 | 출시 후 업데이트 | 예쁨은 베타 통과 기준이 아니다 | 이해 가능하고 눌릴 수 있으면 통과한다 |
| 최적화 문제로 개입이 조금 늦거나 체감상 무거움 | 출시 후 업데이트 | 사용 가능하면 베타 검증 가능 | 기록만 남기고 손대지 않는다 |
| 최적화 문제로 먹통, 크래시, 심각한 지연이 발생함 | 출시 전 필수 수정 | 사용 불가 상태다 | 원인 범위만 최소 수정한다 |
| 불안정한 부가 기능 | 출시 전 필수 수정이 아니라 제거 또는 숨김 | 고치는 것보다 덜어내는 편이 빠르다 | 베타 범위에서 제외한다 |

강제 분류 규칙:

- `불일치` 는 고친다.
- `비효율` 은 출시 후로 보낸다.
- `미감` 은 전부 출시 후로 보낸다.
- `최적화` 는 먹통, 크래시, 치명적 지연일 때만 출시 전 항목이다.

## [D-Day까지의 3단계 실행 로드맵]

### 1. `2026-04-06` ~ `2026-04-07`: 범위 절단

한 번에 수행할 작업은 아래 3개를 넘지 않는다.

- 대표 방해 사이트 `4개`와 베타 핵심 루프 `1개`를 고정한다.
- 현재 문제 목록을 모두 적고 각 항목에 `출시 전` 또는 `출시 후` 둘 중 하나만 붙인다.
- 불안정한 부가 기능은 고치지 말고 숨기거나 끈다.

완료 조건:

- 베타 범위 밖 기능이 명시적으로 제외되었다.
- 모든 남은 작업이 `출시 전 필수` 또는 `출시 후 업데이트` 로 나뉘었다.

### 2. `2026-04-08` ~ `2026-04-09`: 핵심 루프 수리

한 번에 수행할 작업은 아래 3개를 넘지 않는다.

- 상태 불일치를 핵심 루프 기준으로만 수정한다.
- 크래시, 먹통, 치명적 지연만 수정한다.
- 수정 후에는 핵심 루프를 수동으로 다시 확인한다.

완료 조건:

- `설정 -> 개입 -> 선택 -> 저장` 흐름이 끊기지 않는다.
- 베타 사용 중 앱이 멈추거나 무너지지 않는다.

### 3. `2026-04-10` ~ `2026-04-11`: 동결 후 강제 출시

한 번에 수행할 작업은 아래 3개를 넘지 않는다.

- 신규 기능, 미감 polish, 구조 개선을 중단한다.
- `npm run build` 와 수동 스모크 체크 5개만 수행한다.
- `2026-04-11`에 아래 연기 조건이 없으면 바로 출시한다.

수동 스모크 체크 5개:

1. 설치 또는 로드 후 설정 화면 진입
2. 대상 사이트 설정 저장
3. 대상 사이트 진입 시 개입 발동
4. 사용자의 선택 결과 반영
5. 재시작 후 설정 및 결과 유지

## Forced-Ship Rule

아래 3개 중 하나가 아니면 출시를 연기하지 않는다.

- 개입이 발동하지 않는다.
- 사용자의 선택 결과가 저장되거나 반영되지 않는다.
- 사용 중 크래시 또는 먹통이 발생한다.

아래 항목은 출시 연기 사유가 아니다.

- 화면이 아직 덜 아름답다.
- 내부 구조가 마음에 들지 않는다.
- 더 최적화할 수 있을 것 같다.
- 더 많은 사이트를 지원하고 싶다.
- "조금 찜찜하다" 수준의 불편함이 남아 있다.

## Release-day checklist

출시일에는 아래 체크만 본다.

- [ ] 범위 밖 항목이 다시 끼어들지 않았는가
- [ ] 핵심 루프가 대표 방해 사이트 `4개`에서 재현되는가
- [ ] `Shortform Block` 이 YouTube/Instagram/TikTok에서 각 플랫폼 계약대로 동작하는가
- [ ] X의 사이트 전체 마찰과 TikTok의 별도 Feed Flow 과제를 Shortform 계약에 섞지 않았는가
- [ ] `npm run build` 가 통과하는가
- [ ] 연기 조건 3개에 해당하는 결함이 없는가
- [ ] 오늘 추가한 작업이 3개를 넘지 않는가

## Change guidance

- 출시 기준이 바뀌면 이 문서의 MVP gate와 forced-ship rule을 먼저 수정한다.
- 베타 범위 사이트 수나 핵심 루프 정의가 바뀌면 같은 변경에서 이 문서도 함께 갱신한다.
- UI polish나 구조 개선 backlog는 이 문서에 추가하지 말고 별도 backlog 문서나 이슈로 보낸다.
