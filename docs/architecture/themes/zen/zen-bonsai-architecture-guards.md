- Status: Active

- Last validated against code: 2026-10-08
- Path policy: planning-allowed

## Purpose
G15.4 product engine 경계와 retained Classic2 comparison lineage의
owner/readiness/storage 경계 퇴행을 정적으로 차단한다.

## Interpretation Guide
- 이 문서의 규칙은 mainline 안정성을 위한 기본 가드레일이다.
- 실험/브랜치 단계에서는 예외를 둘 수 있지만, mainline 전에는 가드 통과 상태로 수렴한다.
- G15.4 범위 검토(2026-09-05): 현재 Home backend는 `pixi_g15`이며 canonical Canvas2D executor가 scene-command run을 texture로 bake한다. 아래의 Sakura fixed-pass/Classic2 lineage 규칙은 comparison 경로에 적용한다. G15의 실제 성장·개화 연결 상태는 [G15 product owner](./zen-g15-product-engine.md)를 따르며, structural guard 통과를 생물학적 성장 연속성이나 시각 품질의 검증으로 해석하지 않는다.
- 저장 호환성 검토(2026-10-08): [current-only 저장 정책](../../storage/storage-versioning-and-migration-policy.md)에 따라 pairwise model은 exact V5 envelope, 현재 keyspace/latent shape/generation semantics를 검증하고 incompatible presence를 쓰기 없이 거절한다. migration marker나 startup model replay는 없다. `useZenLearningLab`은 current history의 newest-first 순서와 cross-boundary semantics를 검증하며, 시간순 replay는 `SakuraMorphologyPreferencePosterior`의 유효한 현재 evidence에 대한 derived-posterior/calibration 재계산만 소유한다. live feedback과 basin/reliability 통계는 `SakuraPairwiseEvidencePolicy`의 동일 eligibility를 사용한다.

## Guardrail Rules (Mainline)
1. 핵심 파일 존재
2. pass-to-pass import 지양
3. cross-tier recursion token 지양
4. 오케스트레이터 호출 순서 기준 유지
5. pass context factory 사용 기본 적용
6. branch generator의 pass input builder 호출 횟수 기준 유지
7. pass 내부 raw `gene[...]` bracket access 지양
8. pass 내부 raw `gene.xxx` 직접 접근 지양
9. Classic2 lineage identity/graph fingerprint와 all-parent-causal development-record 계약 유지; retired/blocked topology disposition 금지
10. lineage persistence는 단일 typed Zen ModelState key만 사용
11. lineage write는 proposal-outside-transaction + bounded typed CAS chain만 사용; direct set과 updater-in-transaction fallback 금지
12. CAS conflict latest state는 strict normalize하고 exact-reference no-change는 verify-only로 검증
13. Classic2 lineage mode가 wood clock의 단일 owner다. current-runtime Home의 `durable_main`은 `persisted_history`, 명시적 presentation scene과 Experiment의 `ephemeral_preview`는 `ephemeral_scrub`으로만 파생하며 surface가 clock을 따로 선택하지 않음
14. current-runtime Main renderer는 durable lineage ready 전 활성화 금지; ephemeral scene은 durable key 접근 금지
15. G15.4 product engine과 Classic2 comparison lineage에서 vNext/detached research runtime import 금지
16. `ZenBonsaiModelCatalog.js`가 ID/role/surface/default/display의 단일 owner이며 Home default와 Experiment 기본값/reset은 `g15_4`; `classic2`/`classic`은 comparison-only, `vnext`는 research-only
17. unknown model ID와 잘못된 surface/model 조합은 fail-loud 하며 Main에서 comparison/research model로 fallback 금지
18. Classic2 wood presentation은 release V1 `classic2_wood_presentation_v1`, shared trunk-mass knots, `naturalGirthAge`/presented `girthAge`, 명시적 wood-clock policy를 한 owner에서 통과
19. lineage active contract는 `classic2_development_lineage_release_v1` 하나만 허용하며 migration/legacy read 없이 prepared candidate와 bounded CAS를 통과
20. retained development-observation policy는 terminal-carrier metadata/fingerprint와 canonical history를 읽을 수 있지만 branch admission/topology에는 영향을 주지 않으며 이미 기록된 observation은 normal reconcile에서 다시 열지 않음
21. Sakura nebari는 shared renderer 한 곳에서만 생성하고 projected root `girthAge`, immutable geometry seed, 별도 moss surface seed를 사용
22. pot/soil/nebari는 BACK static layer, glazed pot-front occlusion은 FRONT layer가 소유하며 optional ground shadow가 pot/nebari admission을 제어하지 않음
23. `classic2_growth_experience_release_v1` checkpoint owner와 matrix evaluator는 immutable candidate topology/carrier를 직접 분모로 삼고 growth 100을 완성점으로 root length/width, nebari base/trunk join, aggregate wood, branch/carrier coverage, bud/half-open/full 비율, activation delta를 함께 측정
24. retained Main bonsai canvas는 exact current readiness와 paint visibility를 분리한다. 동일 physical canvas/scene/active-tree identity에서는 input/materialization 전환 중 마지막 exact-ACK paint를 유지하되 readiness로 재사용하지 않고, scene/tree identity 또는 canvas가 바뀌면 새 exact ACK 전까지 paint를 숨김
25. Zen koi roster memory read는 `getValue` cold-read만 사용하고 write-on-read bootstrap을 금지한다. 빈 durable root는 background profile-generation install/reset에서만 materialize하며, 기존 valid generation에서 root만 빠진 경우에도 그 같은 bootstrap transaction만 보완할 수 있다. durable hydrate/persist/clear 실패는 세 named runtime error로 surface를 중단하고 empty/in-memory continuation을 금지한다
26. Sakura generation, pot dimensions, structural topology, scene measurement는 structural species seam이 한 번만 소유한다. dependency-injected `sakuraTopologyGenerator.js`와 shared trunk/scaffold generator를 통해 full/structural logic을 복제하지 않는다. `SakuraSpecies.js`는 structural/render species를 조합하는 full surface이고 `SakuraRenderSpecies.js`는 이미 materialized된 topology를 그리는 renderer-only surface다
27. Classic A/B worker는 narrow `api/structuralAB.js`와 frozen `SakuraStructuralABSpecies`의 default phenotype, pot dimensions, structural topology method만 사용한다. default-full generation과 measurement를 노출하지 않으며 broad `api/researchLearning.js`, full/measured Sakura species, canopy/twig emitter, `sakuraRenderer`, `ZenPotRenderer`가 worker module inventory에 도달하면 실패한다
28. Structural A/B scoring의 shared blend 계산은 render-free `candidateScoreBlending.js`가 소유한다. `CandidateScoreModel`이 broad `ZenCoreScoring`을 import해 renderer/config graph를 다시 끌어오는 것을 금지한다
29. `structuralAB.js`는 development research entry다. public manifest, Rollup module inventory, packaged artifact에 포함하지 않는다
30. active trunk planner는 `sakura_macro_spine_intent_bend_aware_v1` 하나다. `MacroSpineIntentPlanV1`이 root-to-apex 형태의 SSOT로서 `rest`, `flow`, `sweep`, `shoulder/core/shoulder`, `compound bridge` span과 finite support를 명시하고, bend-aware fitter가 그 역할과 support를 cubic metadata까지 전달한다. active trunk learning channel은 `trunk_curve_amp → curve-event angle`, `trunk_curve_freq → 최대 3개 curve event의 count와 bin 내부 연속 비주기 cadence`, `backbone_tilt_bias → global posture profile(turn distribution + arc reach)`, `backbone_sway → 별도 finite-support lateral sweep`, `trunk_kink_prob/angle → articulated event gate/angle`로 하나씩만 소유한다. root heading은 수직 constraint로 고정하고 global posture profile은 `backbone_tilt_bias`만 소유한다. raw `trunk_main_curve`, `trunk_wave_amp/freq`, `trunk_roughness`는 compile boundary에서 fixed proposal prior로 정규화하고 active Lab control/preset에서 노출하지 않는다. tilt/sway를 Gemini mainCurve/waveAmp/roughness로 mirror하거나 curve amp/frequency를 generic scaffold/twig curvature에 쓰거나 tilt로 scaffold side identity를 바꾸지 않는다. 3–7 anchor C1 guide는 authored/reference conditioning 입력과 진단 projection이며 active morphology를 다시 소유하지 않는다. legacy main curve/wave/roughness와 32-step heading integration은 `sakura_segment_flow_proposal_v1` ablation/proposal API에서만 호출할 수 있다. exact subcubic은 scalar curve로 재근사하지 않고 `exactCubicControl` carrier로 topology와 renderer까지 전달한다. emission subdivision은 min 8 / base 12 / soft 32 / hard 48이며 순수 render carrier다. canonical `targetAdjacentArcRatio=4`는 arc-midpoint redistribution의 best-effort 품질 목표이고 hard cap 48이 최종 절대 계약이다. 목표 미달은 valid generation을 실패시키지 않고 `achievedMaxAdjacentArcRatio`와 `arcBalanceLimitedByHardCap`으로 드러낸다. span 수는 structural depth, anchor 수, scaffold 밀도, lineage identity의 owner가 아니다
31. scaffold identity와 RNG는 `sakuraScaffoldArcStationPlan.js`의 stable `arcNorm`/`stationId`가 소유하고, root의 x/y/tangent/taper width/turn sign은 `resolveSakuraTrunkMacroStationGeometryV1()`이 continuous macro shape의 global arc에서 직접 표본화한다. `placementId`만 guide shape 변경을 반영하며 trunk span registry와 span-local `attachT`는 render parent lookup만 제공한다. `scaffoldDepth=1` root는 exact `sakura_scaffold_root_arc_attachment_v1`을 보존하며 continuation은 `scaffoldRootId`만 전파한다. active pass에서 physical span geometry/RNG, segment-index/depth projection, `scaffoldAnchors`, scheduled depth, nearest-depth fallback을 금지한다
32. `ZenSpineGuideEditor`는 Single workspace의 ephemeral local draft다. settings/model state/lineage에 저장하지 않고 current Single과 다음 structural A/B batch가 같은 fixed generation context를 사용한다. canonical active identity의 `spineGenerationConditionId`는 direct guide condition 또는 reference-family condition ID 하나이거나 `null`이며 durable genesis/default는 `null`이다. authored ephemeral condition은 generation identity fingerprint에 포함되고 condition 변경은 isolated preview lineage를 `ephemeral_preview_identity_rotation`으로 교체한다. durable identity와 다른 condition을 preview 위에 덮어쓰거나 silent fallback하는 것은 금지한다. condition은 학습 factor가 아니며 A/B 양쪽에서 동일해야 하고, 변경 시 진행 중인 batch와 stale pair를 무효화한다
33. active cutover의 compatibility key는 `sakura_generation_semantics_v5`다. V5는 explicit MacroSpineIntentPlan, non-periodic bend rhythm, role-constrained fitting, conditioned-intent guide provenance, physical tessellation과 biological depth의 분리를 관측한 의미다. pairwise model/prediction contract는 V5이며 exact-current semantics history만 derived-posterior replay/reliability population에 포함한다. model load는 exact current envelope/version/keyspace/latent shape/semantics를 거절 경계로 유지하며 migration marker나 startup replay를 만들지 않는다. V4를 포함한 과거 semantics를 현재 형태 증거로 묵시적으로 재해석하지 않는다
34. A/B question lane cursor는 canonical non-anchor history에서 reload되어 4:1 within-form preference / cross-form coverage cadence를 이어간다. structural discovery는 같은 seed·같은 latent·같은 variant의 서로 다른 exact form을 비교하는 `form_discovery_pair`이며 latent mixed/diversity pair가 아니다. optimize reliability는 current `modelContractId`를 가진 controlled within-form prediction의 표본량과 random-baseline 대비 log-loss skill만 사용하며 coverage 질문 수나 무판별 `p=0.5` 출력으로 해제되지 않는다
35. `TrialContract`의 outer contract version은 release V1인 `1`을 유지한다. `structural_scout_v1`, `lane_split` objective, exact form condition, question lane, generation semantics v5 같은 pre-release shape 강화는 V1을 완성하는 것이며 구현 revision을 이유로 envelope version을 올리지 않는다
36. structural morphology와 biological recursion은 adaptive emission span 수를 읽지 않는다. physical trunk span의 `currentDepth`는 root의 biological depth를 그대로 보존하고 downstream이 실제 소비하는 `trunkMainDepth`만 carrier 순서를 표현한다. `structuralMaxDepth`는 scaffold/twig recursion cap이며 8–48 span subdivision으로 확대하거나 trunk termination에 사용하지 않는다. `BonsaiStructuralDescriptorModel`은 trunk를 stable arc 64구간으로 재표본화하고 fixed macro-turn 8구간에서 turn/inflection을 계산해 같은 연속 spine의 subdivision 변화에 불변이어야 한다
37. Sakura twig silhouette/density는 semantic `branchOrder`와 scaffold/twig role depth가 소유한다. `sakuraTwigSilhouettePolicy.js`의 crown negative-space/open-fork 정책은 adaptive trunk span count나 traversal depth를 읽지 않으며, apex를 단조 증가 budget으로 과밀화하지 않는다
38. emitted trunk span은 연속 `[0,1]`의 exact `trunkArcStartNorm`/`trunkArcEndNorm`을 가진다. Classic2 durable lineage는 `trunkGuideShapeId + 전체 arc length + base width + [0,1]`을 가진 macro trunk descriptor를 정확히 하나만 저장하고 scaffold root는 station ID를 logical node ID로, global arc를 logical `attachT`로 사용한다. logical candidate graph budget은 2,400이고 render-only physical traversal budget은 별도의 2,448이다. 8–48개 adaptive trunk span은 비저장 branded render binding을 통해 macro root decision에 투영되며 request signature/CAS/storage에 들어가지 않는다. 두 budget은 서로 대체하거나 한쪽의 여유로 다른 쪽을 우회할 수 없다
39. `ZenBonsaiClassic2CandidateGraphContract.js`는 descriptor 단건 검증에 그치지 않고 graph 전체를 검증한다. 정확히 하나의 macro root, parent에서 역산한 exact `childIds`, role/depth hierarchy, cycle 부재, root에서 모든 node로의 reachability를 확인한 뒤에만 root와 fingerprint를 반환한다. prepare와 hydrate는 같은 validator/root/fingerprint owner를 사용하며 orphan, disconnected island, stale reverse edge를 저장·재지문하지 않는다. articulated-bend/guide-handle cutover처럼 같은 canonical input의 guide shape 또는 station-root attachment를 바꿀 수 있는 변경은 `classic2_macro_lineage_graph_v2`와 development baseline `2`가 함께 소유한다. Baseline `1` profile은 stale aggregate를 deep-hydrate하기 전에 canonical reset-only recovery로 분류한다. exact cubic carrier만을 위해 persisted node field, read repair, legacy graph reader, implicit identity rotation을 추가하지 않는다
40. Classic2 trunk growth는 physical span별 birth/extension interval이 아니라 하나의 continuous global-arc frontier와 additive arc integral로 투영한다. 각 physical span은 자기 `[arcStart, arcEnd]` 구간을 같은 profile에 질의할 뿐이며 동일 guide의 subdivision 변경은 visible frontier, 총 extension, lineage identity를 바꾸지 않는다
41. topology generator는 `sakura_trunk_macro_render_attestation_v1`에 guide shape, physical trunk span count, entry angle/length/width/curve/arc의 geometry fingerprint를 stamp한다. macro intent span, exact guide partition, physical lineage fingerprint는 `SakuraMacroLineageIdentityContract`의 소수 7자리 identity quantum을 공유한다. intent boundary와 guide segment boundary가 그 quantum 안에서 거의 겹치면 exact partition owner가 절단 전에 guide boundary로 canonical snap하여 정규화 뒤 폭 0인 physical span을 만들지 않는다. 이는 후보를 대체하거나 geometry를 사후 보정하는 fallback이 아니라 동일 identity로 구분할 수 없는 두 절단점을 분할 전에 하나로 확정하는 계약이다. prepared render binding은 이 fingerprint와 exact physical node coverage를 묶고, projection 직전 `requireZenBonsaiClassic2LineageRenderBindingForTopology()`가 현재 topology를 다시 순회해 root, 전체 node set/count, trunk continuity/arc, guide, geometry, role별 logical mapping을 검증한다. branded binding이라는 이유만으로 다른 topology에 재사용하거나 mismatch를 보정하는 fallback은 금지한다
42. active single-root 수형 생성 계약은 `formal_upright`, `umbrella_crown`, `slanting`, `informal_upright`, `literati`, `full_cascade`, `semi_cascade`, `weeping`의 정확히 8개다. `BonsaiSingleRootFormCompositionPrior`가 trunk posture/curvature, scaffold station/density/side/downward ratio, crown envelope, negative-space window의 목표를 함께 소유하고, `sakuraSingleRootFormCompositionAdapter.js`가 이 목표와 bounded latent residual을 합성한다. form 입력은 명시적 opt-in이며 입력이 없으면 Home의 기존 latent-only 생성이 유지된다. full과 structural scout는 같은 plan/provenance를 사용하고 adaptive subdivision은 이를 바꾸지 않는다. `BonsaiFormClassifier`는 결과를 읽는 read model일 뿐 generation owner가 아니다. `twin_trunk`와 `multi_trunk`는 single-root topology에서 fail-loud하고 `low_triangle`은 `formal_upright`의 crown composition target일 뿐 별도 form ID가 아니다
43. A/B coverage와 preference는 별도 evidence lane이다. `BonsaiMorphologyEvidenceContract`가 generation semantics, descriptor/classifier version, exact target form, 20D visual vector와 classification snapshot을 history에 저장하며, primary ID/score는 정렬된 첫 membership 및 고정 classifier threshold와 일치하고 secondary ID는 같은 membership snapshot에서 정확히 파생되어야 한다. coverage lane은 form-balanced cross-form 질문으로 global form bias를 갱신하지만 latent GP·preference basin·predictive reliability에는 들어가지 않는다. coverage 진단도 explicit `structural_discovery` row의 A/B evidence만 집계하고 preference/Sobol row를 proposal 또는 realization count에 섞지 않는다. scheduler가 제안한 target의 form count/entropy/ratio는 proposal coverage로만 보고하고, 실제 primary coverage count/entropy/ratio는 fallback 없이 `classification.primaryFormId`만 집계한다. 이와 별도로 모든 지원 form membership 중 score가 저장된 classifier threshold 이상인 hit를 realized-membership count/entropy/ratio로 집계하며, unsupported primary라도 supported secondary membership이 유효할 수 있으므로 membership evidence 수를 supported-primary 수로 제한하지 않는다. target별 생성 수용률은 해당 target membership score가 threshold 이상인지로 total/per-form을 별도 보고한다. target이 균형이어도 primary classifier 결과가 한 form으로 붕괴하면 realized-primary coverage는 100%가 될 수 없다. discovery replay는 cross-target이면서 두 실제 primary도 서로 다른 지원 form이고 양쪽 target membership이 threshold를 통과한 row만 global cross-form posterior에 넣는다. preference/Sobol replay는 same-target이며 양쪽 실제 primary가 그 target과 정확히 같고 target membership이 threshold를 통과한 row만 해당 per-form posterior에 넣는다. 부적합 row는 exact reason counter로 노출하고 lane/context 충돌은 실패한다. history envelope은 canonical ISO timestamp와 unique safe-integer ID의 strict newest-first 순서를 계약으로 검증하며, replay owner는 이를 조용히 정렬하지 않고 검증된 배열만 뒤집어 시간순 predict-before-train held-out Brier/log-loss/directional accuracy/variance를 global cross-form과 per-form same-primary로 분리한다. count heuristic을 confidence로 부르지 않는다. preference/cold-start lane만 controlled latent GP evidence이며 exact morphology evidence가 있으면 global + per-form visual posterior도 함께 갱신한다. A/B generation admission은 `zenABGenerationReadiness`가 hydrated canonical profile, exact Sakura species, learning-state load, cold-start readiness를 함께 소유한다. profile hydration 전에는 plan을 만들지 않으며 profile admission 뒤의 null/unsupported species는 대기 상태나 empty selection으로 낮추지 않고 정확한 오류로 실패한다. candidate pair는 최소 지원 card viewport인 240×240 CSS px에서 동일 physical scale로 비교하고 7.5px visible-distance 하한을 통과해야 한다. 더 큰 실제 card는 이 보수적 admission보다 거리를 줄이지 않으며, 어느 한 축이라도 240px 미만인 card는 비교 surface로 paint하지 않는다. 하한 미달 pair는 재시도할 뿐 완화·fallback·강제 latent 증폭하지 않는다. 후보가 하나도 남지 않으면 controller는 trial planning, source-pair reconstruction, visible-distance admission을 구분한 attempt diagnostics를 보존한다. packing은 candidate form provenance에서 파생한 policy/form/variant context와 이미 들어온 context가 하나라도 다르면 값을 덮어쓰지 않고 실패한다. morphology evidence가 있는 history row는 generation context, A/B candidate, A/B render, evidence의 generation semantics가 모두 현재 exact semantics로 일치해야 하며 불일치를 replay 전에 실패시킨다. proposal coverage, realized-primary coverage, realized-membership coverage, target acceptance와 global/per-form preference calibration은 서로 다른 진단으로 보고하며 generation semantics가 바뀐 evidence를 현재 의미로 재사용하지 않는다
44. `zenBonsaiRenderPlan.js`는 materialized topology를 model-specific immutable render plan으로 보내는 narrow dispatcher다. Classic2/classic의 `zen-sakura-render-plan-v1`은 development projection, visible branch graph, exact cubic carrier, terminal life/activation gate·reach·scale·paint radius, anchor, bounded motion reserve와 full-render bounds를 한 번 계산하는 render-only SSOT다. G15.4의 `zen-bonsai-g15-render-plan-v1`은 promoted graph에서 만든 exact scene-command stream, source topology signature, device surface, background/pot policy, 선택적 scene-local planting camera anchor를 소유하며 Classic branch root를 합성하거나 Sakura plan validator에 들어가지 않는다. shared `useZenTreeRenderer` core가 topology/materialization/surface별 plan을 한 번 만들고 scene snapshot과 renderer가 같은 identity를 소비한다. Sakura plan은 camera, Canvas2D worker/local preview, Pixi branch rig에 전달되고, G15 plan은 unified Home worker의 `pixi_g15` backend에서 scene builder가 확정한 intrinsic canvas coordinates를 유지한다. canonical Canvas2D executor가 depth-ordered command run을 cropped texture로 bake하며 frame별 motion은 shared hierarchical rig transform이 소유한다. Home planting anchor가 있으면 같은 G15 scene builder camera가 world origin을 그 scene-local anchor에 매핑한 뒤 command stream을 동결하며, 외부의 두 번째 camera가 이를 재해석하지 않는다. Home은 `useZenHomeTreeRenderer`, Lab/A-B/VNext preview는 `useZenLabTreeRenderer`에서 서로 겹치지 않는 renderer hook set을 주입하며 Main entry가 local/A-B renderer를 정적으로 import하지 않는다. settings `ZenBonsaiPreview` facade도 runtime을 nested dynamic import하여 preview가 열리기 전에 local renderer/species closure를 Home static closure와 합치지 않는다. structured clone 뒤 worker는 해당 model validator로 재검증·재동결한다. G15 validator는 submitted topology에서 scene을 exact rebuild하여 topology/scene/plan signature mismatch를 실패시키며, 검증된 identity는 WeakSet fast path로 frame 중 재빌드하지 않는다. Sakura bounds/Canvas/Pixi가 growth projection이나 terminal visibility를 다시 계산하는 것을 금지하고 Pixi texture bake의 quantized activation presentation과 runtime presentation은 Sakura plan 안에서 명시적으로 분리한다. `zen-sakura-full-render-bounds-v1`은 Sakura plan bounds의 camera 호환 projection이며 G15 intrinsic viewport를 두 번째 camera owner로 재해석하지 않는다. scene snapshot은 plan의 topology signature를 전달받아 exact match를 검증한다. structural A/B comparison bounds는 texture-free structural preview segment와 reference pot만 측정하며 full-scene `measureBonsaiSceneBounds` 또는 `ZenPotRenderer`를 import하지 않고 full-render fit과 합치지 않는다. Home garden-bed의 bed projection은 frame 밖으로 확장할 수 있지만 tree paint는 G15/Sakura Canvas2D clip과 Sakura Pixi mask에서 `sceneViewport`로 제한한다. 모델 중립 `zenBonsaiOpenAirBackdrop`은 canonical Zen environment state에서 시간대 sky/horizon/light/floor를 그 scene viewport 안에 그리며 topology/camera를 다시 소유하지 않는다. 실제 alpha 진단은 Sakura plan에만 허용되는 `zen-sakura-actual-alpha-observation-v1`의 명시적 one-shot, tree-only, pre-clip, device-pixel 요청이며 scene/commit/render-plan/materialization/input/surface identity가 모두 일치해야 한다. G15 plan에서 이 observer를 요청하면 fail-loud한다. 최종 framebuffer, 상시 readback, durable state, Trial/evidence 저장을 금지한다. sampler가 연결되지 않았거나 요청되지 않은 Sakura 실행은 `observedAlphaBounds: null`, `observedAlphaBoundsStatus: not-sampled`로 남겨 predicted envelope를 실제 pixel evidence로 오인하지 않는다
45. production Home Canvas2D/Pixi worker는 main runtime이 materialize한 topology만 소비하며 `SakuraRenderSpecies.js`, `sakuraSpeciesRuntimeContract.js`, `resolveRenderSpecies()`만 사용한다. renderer source가 generation-capable `resolveSpecies()`, `ZenCoreSpeciesRegistry.js`, `SakuraSpecies.js`, `SakuraStructuralSpecies.js`, `SakuraStructuralABSpecies.js`, `sakuraTopologyGenerator.js`를 직접 소유하면 architecture guard가 실패하고, worker artifact contract는 cross-entry shared chunk를 포함한 전체 closure 크기와 금지 경계를 별도로 검증한다. worker bundle 예산을 맞추기 위해 generation semantics를 삭제하거나 baseline을 올리지 않는다
46. Sakura render plan의 `signature`는 derived bounds/envelope를 제외한 전체 canonical paint/source payload를 정확히 소유하고, `bakeSignature`는 runtime wind·deferred sag와 surface/camera를 제외한 Pixi texture payload만 소유한다. ## Boot handoff input stability

`useZenClassicHomeTopologyRuntime` retains G15 topology while the seed/life/phenotype
values are unchanged. `useZenBonsaiRenderPlan` retains the plan for identical
device geometry and topology identity and isolates Classic-only presentation
inputs. Neither optimization skips materialization signatures, structured-clone
validation, surface validation, or scene acknowledgement.
