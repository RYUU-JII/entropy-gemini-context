## Purpose

Settings Protection is the public editor of the cooling preset and independent
Site/Global goal reminders. Tools retains family curve/fixed mode, effect
activation and maximum strength. Furin is a read-only scoped-policy/prerequisite
projection with a Settings link and an explicit temporary pause/resume action;
its selected controller exposes no alternate `setNudgeConfig`, child toggle or
recommendation writer. Pause uses `artifactControlState` and preserves both
goal preferences. Barrier consumption interval remains independent.

Lens, Veil, Brake and Barrier each expose one app-owned `cooling-curve-mode`
dock block through `CoolingCurveFamilyControl.jsx`. Its curve/fixed selection
uses the canonical `useProtocolStore.setCoolingCurveFamilyMode` command; pending
and failed writes remain visible and no ON/OFF setting is changed. Furin/Gate
and the independent Barrier consumption interval have no curve-family control.
Defaults and exact settings are owned by `coolingCurvePolicy.js`; Settings
Protection owns the one gentle/standard/steep preset. Dev Filter retains a
read-only summary and diagnostic preview. Theme artwork never writes these
settings. The nullable advanced value is persisted now; its editor is P3.

The gallery measures a stable scene viewport and consumes the theme profile's
declared navigation variant. Named quickbar navigation stays below the scene in
normal flow; Zen's sequential path has only the two edge thresholds, with no
visible position index or reserved lower band. Previous/next, keyboard, wheel
and swipe navigation wrap among disclosed families. Locked families are skipped
and cannot commit selection or open an introduction popup. Named quickbar
variants expose their canonical unlock day as readable navigation content.
The selected panel owns the visible artifact name, ordinal and identity
sentence; the path's polite live region still announces the selected artifact
and position. Its root exposes the ordered family inventory, locked families,
current family and pending admission as read-only DOM metadata for existing QA
readers; there are no hidden decorative nodes or alternate selection controls.
Failed preparation keeps its explicit retry in the scene. Each control owns
its inline effect explanation and reserved current-option feedback. Zen discloses
these together in one keyed accordion row at a time; collapsed rows show only
the name, configured-state ink and an optional short value. There is no
duplicate automatic family card or info popover. Disclosure refresh failures stay
in the workspace status row, preserving the current scene and explicit retry.
Furin observes the independent Site/Global goal-end settings edited in Settings
Protection. Its one temporary pause/resume action changes only the Flare family
suspension and is disabled during global pause. Time boundaries are edited in
Sites; neither the Furin card nor its selected controller writes `nudgeConfig`.
`furinTimeAvailability.js` consumes canonical recording/cap admission to explain
configured time connections or a pending reason in the control’s reserved feedback,
with one state-specific Sites/recording-setting continuation when needed. It does
not claim runtime engagement. No separate installation form, always-visible Site-only
explanation or public replay entry remains. Existing pending installation receipts
use the guidance owner in `../guidance/guidance-runtime.md`; destructive Echo review keeps its existing auth,
backup, pending navigation and actual-deletion contracts.

Configured ON, browser permission admission and current page engagement are
separate projections. The selected dock consumes `applicationStatus` rather than
leaving prerequisite/read failures in unused card metadata. One inline continuation
opens the owning Sites or Settings section, or retries the failed permission/runtime
read; no navigation or permission request happens on mount. Furin uses its reserved
control feedback instead of a second dock status. OFF or paused Furin stays OFF or
paused. A current permission/runtime failure precedes its time prerequisite until
the owner read recovers. Retry stays pending through ACK, reports returned as well
as thrown errors, and fences responses from an earlier continuation.

`browserPermissionSnapshotResource.js` owns one Chrome `onAdded`/`onRemoved`
subscription from its first read through this dashboard document's lifetime.
Events invalidate the shared typed snapshot before notifying active consumers.
Parked consumers stop reading, while cache invalidation continues so reentry cannot
reuse permissions revoked while Tools was inactive. Resource reset releases that
subscription and fences older reads. The capability hook alone publishes its
generation-fenced success/failure; an initial effect cannot republish an older error.

Zen's stacked portrait panel gives its identity header the intrinsic height of
the title and inscription, without the desktop rail's 30-percent share. The
existing control garden remains the scroll owner; header copy cannot shrink
into the title or be clipped to a partial line.

The production Zen gallery engine and seven-scene comparison are owned by
[`zen-artifact-engine-review.md`](../themes/zen/zen-artifact-engine-review.md).
The declared `ArtifactGalleryVisual` is the stable production host. Individual
`Artifact_*` widgets remain standalone ritual/reference entries. Shoji, GreatWave, Enso and
TomeIshi share presentation recipes with it; the Furin/Shishi executors reuse
their existing physics and vector recipes. Settings and controllers keep their
production owners.

The production host presents completed Worker bitmaps in the same React layout
commit as placement and stage effects. `ZenArtifactGallerySession` owns renderer
retention under the dashboard theme-lifetime seam; `ZenArtifactWorkerClient`
owns bounded requests and transferable frame disposal. The existing physical
Worker has an `artifacts` logical channel, with no new physical Worker or Main
first-frame gate. Standalone content ritual renderers keep their current owners.

All theme artifact motion consumes the Tools owner's `isRuntimeActive` admission
through the canonical render context. Leaving Tools parks retained animation
immediately; keeping its DOM for presentation does not retain runtime permission.
While Tools is active, selected motion remains independent of document or viewport
visibility. Zen's daily Enso checkpoint also advances to the current local day on
reactivation and at the existing reveal boundary, without adding a gallery clock.

The shared disclosure hook unsubscribes parked consumers and retains only their
last committed presentation. Canonical resource invalidation and active consumers
continue normally; reentry selects the latest resource state before the existing
freshness/revalidation read. This does not create a second progression ledger or
skip an admitted refresh. ArtifactGallery shallow-memoizes its complete public
props so an unchanged retained workspace does not rerun its controller/view when
another dashboard surface updates. Activity, disclosure, selection and callbacks
remain inputs, and gallery-owned state/context/subscriptions still update.

All six canonical themes declare every released artifact family and navigation
icon. Clinical and SCP use their own seven SVG instruments in the shared flat
gallery/stage. Their plugin-local presentation adapters consume
`useArtifactRenderChannels`; the common SVG frames own material definitions,
instance-scoped IDs and canonical coordinates. These lightweight instruments
add no Worker, animation clock, settings subscription or cross-theme renderer.
Their seven canonical loaders are validated even when a theme declares none;
zero declarations are an incomplete implementation, not an unsupported state.

The shared flat canvas, control heading, navigation and tooltip consume the
installed `surface`, `surface-sunken`, `on-surface` and `border` tokens so the
same owners support Clinical's light world and the dark worlds. Zen's custom
canvas retains its ambient day/night navigation tone.

Clinical's control and active-navigation accents have their own readable light
surface roles in `themes/core/tools/artifactColorSystem.js`; the object's canonical
material color and glow remain separate. Clinical and SCP's inactive instrument
opacity is owned by `themes/core/toolsVisualPolicy.js`, so an OFF instrument stays recognizable
without admitting motion or suggesting an active protocol.

Zen declares `rendererFx.preserveBodyAppearance` in that same policy owner.
The common `ArtifactRenderStage` preserves whole-body scale, opacity and color
and omits wrapper glow across activity states. The flag adds no theme branch to
the stage and no scene policy to the Worker. Local light, wind, water and internal
materials, entry reveal, and canonical motion/simulation admission keep their
existing owners.

Project:Entropy's artifact world follows orbital instrumentation inspired by
2001: A Space Odyssey: enamel chassis, graphite bezels, precision metal and
illuminated physical controls. `EntropyArtifactFrame.jsx` and
`useEntropyArtifactPresentation.js` own seven distinct vector instruments;
Brake uses `InertialDamper.jsx` and does not borrow the Barrier Monolith.
`EntropyArtifactCanvas.jsx` supplies a static recessed bay and
`EntropyArtifactPanel.jsx` supplies the mechanical control carriage. The gallery's
existing motion owner applies one finite vertical docking stroke on family identity
changes, with no replay on setting/title updates and no travel under reduced motion.
The artifact scene remains preloaded and ready throughout. The existing dashboard
tab-stage motion is separate and unchanged. Backlit buttons show committed/pending
selection through the existing command acknowledgement owner; they add no idle flicker.

Entropy's readable control pigments are separate from its light instrument and
navigation signals in `artifactColorSystem.js`. SCP, Matrix and Cyberpunk's dark control surfaces also
uses light control pigments, including Brake's selected state. Shared default
panels derive corners from theme shape tokens; their local control radius leaves
Zen's own controls unchanged. Cyberpunk declares `CyberpunkArtifactCanvas.jsx`
for the dark signal bay within its light console and pairs navigation foregrounds
with that inset. Matrix and Cyberpunk each declare their own Brake body, and their
Lens/Veil consume the released grayscale/blur/brightness/contrast/saturation and socialMetrics/timeSignals/shortformBlock projections without retired or cross-family children.

Matrix and Cyberpunk's seven bodies separate unlit structural paint from active
signal emission through plugin-local `matrixArtifactMaterial.js` and
`cyberpunkArtifactMaterial.js`. Their inactive stage opacity is `0.86`, including
the final theme/family Lens and Veil overrides in `toolsVisualPolicy.js`; body
edges and captions remain readable without multiplying that dimming through the
main chassis. Active pigments, signal cycles and canonical motion admission keep
their existing owners. The OFF readability defect was observed in Matrix run
`20261004134807512-dashboard-capture-97341552` and Cyberpunk run
`20261004135107498-dashboard-capture-d7b61801`, particularly Brake, Gate and Flare.
Those captures document the pre-correction state, not post-correction QA results.

Each selected family schema publishes its child configuration through
`buildVisualState`. Theme instruments may use this read-only projection for
mechanical posture and material response. Configuration, preview, suspension,
capability and runtime engagement remain separate in the canonical activity
envelope. In particular, an Echo cartridge is not evidence of completed history,
bookmark or tab removal. Operational controls retain shared product copy; the
Clinical/SCP instrument names are localized atmosphere only.

The Tools tab is a control and support surface. It may assemble disclosed
artifact cards, render the selected artifact scene, and expose storage
maintenance actions, but it must not become the canonical owner for disclosure
truth, artifact runtime truth, settings persistence, support auth, storage
inspection, or maintenance side effects.

The practical reading question is:

```text
Can the Tools tab show and operate the control surface without inventing
artifact state, accepting malformed support results, or bypassing background
storage owners?
```

The dashboard owns one UI refresh timer for the ambient presentation. The
gallery does not expose or persist a day/dusk control, and the Karesansui canvas
does not start a second clock. Pond/bonsai worker cadence remains private to
those runtimes; only their canonical solar-environment calculation is shared.

Artifact navigation preserves the workspace, canvas, navigation, and outer
control rail. Zen retains its renderer across family changes; other theme renderers and
panel contents use the artifact identity as a reset key; title/subtitle/description changes are plain
prop updates. Selected controller hooks live in a sibling host and are released
when leaving that family, while their projection is delivered in a layout
effect before paint. Layout-effect cleanup must not clear the published parent
state: Suspense hiding also invokes cleanup and would create a hide/reveal/update
loop (React #185). The boundary expires projections by controller admission and
artifact id instead. Do not wrap the workspace in a conditionally mounted
controller: doing so resets canvas measurement and the whole scene on Echo
entry/exit even when its module is already prepared.

The gallery's prepared artifact selection starts fully visible without entrance
filters. Panels normally do the same; Entropy explicitly declares the bounded
vertical carriage stroke described above. Its renderer FX explicitly disables `entryReveal`,
so flat artifacts do not add a second fade from zero after the ready effect.
Widget/controller readiness still gates the selection commit; this presentation
contract does not bypass preload ACKs or retain inactive family controllers.
The shared render stage publishes `data-artifact-render-stage-ready` from its
actual `isComponentReady` acknowledgement. Runtime QA consumes that ACK rather
than inferring presentation readiness from a selected navigation button; Zen
also requires the requested scene's current bitmap receipt.

Quickbar artifact navigation is the aperture's normal-flow sibling after the
shrinkable scene viewport. Its named navigation uses CSS `auto-fit` columns with a 78px
minimum and 64px minimum-height targets, canonical family order and a selected
cell border. Names and locked timing remain readable without hover. Narrow
fields wrap the same cells into additional rows; navigation reserves its own
height while the scene's existing measurement follows the remaining viewport.
The separate control rail retains its shared dock/Zen garden scroll owner.
Navigation owns no observer, viewport substitute or coordinate-based indicator;
the retired `artifactNavigationLayout.js` helper and detached geometry fixture
are removed. Focus-visible outlines, active/busy/disabled semantics, focus/pointer
preparation and locked non-actions stay in the production navigation owners. Zen's
separate `ArtifactHorizonIndex` consumes the parent's slots, request state,
selection/intent callbacks and resolved copy. Its local CSS owns the hairline
geometry; it adds no settings/runtime read or measurement source. The pipeline
guard protects flow, wrapping, visible labels and control scrolling; component
tests verify production DOM ownership and stable action order. Actual narrow/wide
Chrome hit tests remain browser evidence rather than a pure-helper PASS.

The retained Pixi gallery separates material preparation from frame application.
`ArtifactGalleryView` supplies a pure placement closure; `ArtifactRenderer`
includes it with context/activity/FX in one complete request. The single
`useArtifactPresentationCommit` owner renders only the current prepared candidate
and submits its Pixi frame in a layout effect after DOM mutation, before paint.
The host reuses a matching current displayed ticket for DOM-only publication;
actual pixel inputs (including connected ground and simulation) prepare a new
Worker frame, with material bake governed separately by canonical material identity.
Parking invalidates presentation generation, so tab reactivation prepares a fresh
frame from the retained cache. `onReady` remains a
once-per-family acknowledgement after submission. No `flushSync` or independently
committed placement/FX state exists. CSS stage FX do not interpolate across
retained swaps. No old family controller is retained. `useResizeObserver` owns
the gallery's one initial and reactivation CSS-box read with
`measureBeforePaint: true`; its observer does not repeat the initial read and
disconnects while parked. The last nonzero geometry remains retained. Fixed
navigation slots share CSS size/gap tokens with one retained selection indicator;
selection never requests document-wide Framer `layoutId` projection.

`ArtifactGalleryView` admits the complete theme canvas, including its ground,
only when that existing geometry owner publishes a nonzero viewport. The absolute
metric probe, aperture, navigation and control rail mount independently, so the
first CSS-box read does not construct provisional zero-size ground geometry.
The same retained dimensions keep the admitted canvas mounted across parking and
family selection. This adds no measurement source, default size or paint timer;
actual pixels still follow the complete presentation commit above.

Settings and rendering isolation:

- Only the selected family subscribes to its settings fields. Filter/gate object
  normalization may clone the store map; a bounded structural-sharing selector
  retains unchanged family fields before Zustand/useShallow notifies React.
- Commands patch the latest canonical value inside the existing protocol-store
  updater, preserving sibling fields. This is a read/render split, not a new
  persistence owner, storage mirror, or partial settings snapshot write.
- Every family mutation returns the canonical command acknowledgement. Filter,
  Gate, Flare, suspension and Echo commands reject a returned `error` before
  reporting completion. Composite recommendations wait for configuration before
  unsuspending; failed configuration never resumes the family.
- The recommendation catalog validates child ownership against the canonical
  family catalog. Lens does not configure Brake or Barrier filters, and the
  family command tests apply the actual recommendation through each owning
  handler while preserving sibling settings.
- `themes/core/tools/useArtifactControlCommit.js` owns bounded presentation-only
  pending intent and redacted command failures for the default and Zen controls.
  Settled values come from canonical props. Choosing a non-OFF choice invokes
  only the child value command; that command owns activation plus value, so a
  theme cannot issue a second enable write or change setting semantics.
- Lens and Echo control rows carry their canonical `childKey` as
  `data-artifact-control-child-key`; rendered options expose their declared value
  as `data-artifact-control-value`. The shared row renderer and Zen control box
  preserve these model identities with their pressed/checked accessibility
  state. The integrated protection QA owner uses this bounded identity seam
  for actual settings input, without deriving identity from localized labels,
  row position, or theme appearance.
- Runtime delivery keeps the shared subscription bridge. Its optional stable
  selector projects canonical selected-family summary/children, excluding the
  global capture clock and revision. Errors and scope changes still propagate.
- Unchanged inputs retain the whole card. A control-only change may rebuild the
  selected card, but equal visual/activity/presentation inputs retain identity;
  canvas and renderer props have independent memoization from the control rail.
- Tools critical preload also calls `preloadToolsInitialArtifact`: the shared
  disclosure resource and navigation's `getVisibleArtifactFamilyIds` select the
  first visible family. Only that controller/schema, exact widget, and scene
  modules are admitted. This runs in existing post-first-frame boot/intent work;
  it neither mounts settings hooks nor adds an all-artifact or neighbor sweep.
  Subsequent selection joins the same widget/controller resource records.
- The outgoing gallery is presentation-only retention while a new selected
  controller publishes before paint, including disclosure changes that remove
  the previous item. Reactivation reads current canonical state. No inactive
  family hook tree is cached or kept running.
- Full collection builders remain for explicit fixture/harness consumers; the
  live Tools root must not import them or all-family settings hooks.
  `artifactCardSchemas.jsx` is collection-only. Each lazy selected controller
  imports its own schema; `artifactCardMaterialization.jsx` is the shared card
  validation/materialization owner and imports no family registry.

Development entry telemetry distinguishes root `readiness:ready`, selected
`workspace:ready`, and `presentation:ready` (the Zen bitmap commit). Tools root
readiness has `waitForPresentation: true`; its local observer remains active
until two rAFs after presentation, or error/park/unmount. The historical
`usable-paint` event names a paint opportunity, not physical display time.

## Current Findings

### F1. Tools tab is a switchboard over two real owners

Status: keep.

The tab composes artifact control/gallery surfaces and storage support panels.
Artifact runtime truth stays in the protection artifact control plane, while
storage support side effects stay in background support owners.

### F2. Artifact gallery ownership is already documented locally

Status: keep.

`src/apps/dashboard/tabs/tools/ARTIFACTS.md` correctly identifies the artifact
pipeline and forbids quiet fallback card schemas, business-state localStorage,
and render-saving visibility gates on the selected artifact renderer.

### F3. Storage support controller now validates success payloads

Status: fixed in the 2026-06-29 Tools support pass.

The dashboard support hook now treats invalid inspector snapshots, missing
inspector sections, invalid support action results, unsupported tasks, invalid
auth policy owner output, and task mismatches as visible errors instead of
reporting support success. Successful support actions preserve maintenance
warning codes in the status text so partial best-effort failures do not collapse
into plain success.

### F4. Background storage support route validates support result identity

Status: fixed in the 2026-06-30 storage support route identity passes.

`createStorageSupportActionHandlers()` requires plain object snapshots/results
before returning `success:true`. It also verifies that a support action owner
returns the same task that was requested, so task mismatches fail with
`STORAGE_SUPPORT_ACTION_TASK_MISMATCH` at the runtime route before the response
reaches the dashboard. Destructive reset routes similarly require the
maintenance owner result to identify the reset class that ran:
`{ reset: 'analytics' }` or `{ reset: 'app' }`. The dashboard mirrors these
contracts at the
caller boundary instead of trusting any successful response shape.

### F5. Memory purge artifact workflow has its own boundary map

Status: split in the 2026-06-29 Memory Purge artifact workflow pass.

History cleanup and blocked-bookmark destruction remain Tools artifact controls,
but their destructive preview/confirm/backup/auth/ceremony flow is now mapped
in `memory-purge-artifact-workflow-boundary-map.md`. This keeps the broad Tools
map readable while preserving the stricter dashboard-vs-content ceremony split.

### F6. Artifact capability read failures are no longer permission fallbacks

Status: fixed in the 2026-06-29 artifact capability pass; tightened on
2026-06-30.

`useProtectionArtifactCapabilityState()` reads the browser permission snapshot
through the dashboard permission snapshot resource, whose only underlying read
is `ChromeService.permissionsGetAllStrict()`. The resource deduplicates in-flight
Tools/Settings reads and reuses a successful snapshot for at most 15 seconds;
explicit capability refresh bypasses that freshness window. Read failures are
converted
into a `permission_snapshot_unavailable` capability state. Protection and
memory artifacts remain previewable so the configured ceremony/control surface
stays visible, but runtime application is blocked until the permission snapshot
owner can be read. Missing browser permission APIs, browser-call failures, and
malformed success payloads do not collapse into an empty permission snapshot.
Direct malformed snapshot input is also normalized to
`permission_snapshot_unavailable`.
The Tools capability hook also owns an activity generation: a permission read that
finishes after the tab becomes runtime-inactive may warm the shared resource, but it
cannot replace the retained outgoing capability projection or publish a late error.

### F7. Artifact runtime snapshot failures are no longer ready-state fallbacks

Status: fixed in the 2026-06-29 artifact runtime status pass.

Tools artifacts now receive `artifactRuntimeSnapshotError` from the shared
runtime subscription bridge. Protection artifacts with valid permissions but a
failed runtime snapshot read show `runtime_snapshot_unavailable` instead of the
generic ready-for-protected-sites state.

### F8. Artifact mutation handlers are now required at card build time

Status: fixed in the 2026-06-29 artifact card handler contract pass.

`buildToolsArtifacts()` now rejects missing canonical family state/handler
groups, including family-level `setSuspended` and `applyRecommendation`, before
any disclosed card builder runs.
Veil, Barrier, and Sentinel Flare card
builders no longer install no-op `commitConfig` fallbacks. Their semantic
configuration mutation paths now require the canonical family handler and throw a
handler-specific error if the control-plane contract is missing. Visible child
control rows now follow the same rule for their `toggle`, `setLevel`, `setValue`, and
destructive workflow handlers. The only remaining optional handler in this card
set is the fullscreen visual relaxation auxiliary control, which is rendered only
when an eligible handler exists.

### F9. Scene spec fallback is now diagnosable at runtime

Status: fixed in the 2026-06-29 artifact scene runtime pass.

Tools gallery scene-spec recovery remains bounded because themes may provide
partial scene overrides, but invalid scene-spec values and missing artifact
placements now remain visible on `runtime.diagnostics.sceneSpecWarnings`.
Fallback is no longer console-only evidence.

### F10. Missing renderer widgets are now diagnosable

Status: fixed in the 2026-06-29 artifact renderer widget pass.

The renderer still uses a neutral missing-widget placeholder rather than
cross-theme substitution, but widget lookup status now travels through
`artifactRenderContext.diagnostics.rendererWidget` and placeholder `data-*`
attributes. Missing widgets are no longer console-only evidence.

### F11. Declared control surfaces no longer collapse to empty panels

Status: fixed in the 2026-06-29 artifact control surface pass.

The generic panel components may still render without a control surface for
non-artifact reuse, but the canonical Tools artifact pipeline now requires a
materialized dock with block metadata and rendered content for every artifact.
`materializeArtifactControlSurface()` rejects declared-but-empty surfaces,
invalid dock block kinds, rows without mutation handlers, action blocks without
click handlers, and status/info blocks without their visible payloads.

### F12. Storage support panel buttons no longer install UI no-ops

Status: fixed in the 2026-06-29 storage support panel pass.

The support panel can remain hidden without controller wiring, but once visible
it now requires refresh, run-task, and close handlers. The passcode input
handler is required only when passcode auth is displayed. This keeps support UI
buttons from silently doing nothing if the Tools controller contract regresses.

### F13. Destructive action reviews stay owned and install no UI no-ops

Status: fixed in the 2026-06-29 handler contract pass; moved inline in the

### F17. Artifact color identity is canonical-id keyed and role-scoped

Status: fixed in the 2026-07-11 Zen artifact color-system pass.

truth. It keys colors by canonical artifact id, never gallery index or personal

neither role belongs to color tokens.
